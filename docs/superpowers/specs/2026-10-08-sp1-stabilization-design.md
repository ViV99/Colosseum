Это первый из семи подпроектов приведения Colosseum к задумке. Согласованный порядок: 0+1 (этот документ) → 2 модель игры → 3 игроки, лига, warm start → (4 отбор и наблюдаемость ∥ 5 распределённость) → 6 скорость и расширения.

## 1. Цель

Корректное, наблюдаемое и устойчивое обучение на одной машине на текущем API сред (`BaseEnv`). По итогам подпроекта должны работать:
- 1v1 с одновременными ходами;
- 1v1 пошаговые;
- соло;
- self-play с несколькими агентами;
- лига, в которой все агенты встречаются друг с другом.

Попутно сеть перестаёт быть привязанной к LSTM/GRU: вводится общий протокол модели с состоянием (`PolicyModel`). Он поддерживает модели без памяти (MLP, CNN), рекуррентные и трансформеры с памятью.

## 2. Вне рамок

| Что | Куда |
|---|---|

| Скриптовые, замороженные и внешние игроки; PFSP по снимкам; warm start на агента (`init`, kickstart, прогрев критика); хранение снимков с top-k | SP3 |
| Журнал матчей, OpenSkill/Bradley–Terry, `colosseum tournament`, дашборд, рейтинги снимков | SP4 |
| Хаб и ноды, wire-формат, кэш весов на машину, отказоустойчивость кластера, `max_policy_lag`, K8s/образы | SP5 |
| cuDNN-путь RNN, быстрый unroll трансформера, GPU-инференс на воркерах, инференс-сервер, новые алгоритмы | SP6 |

**Распределённый режим** (`run-learner`, `run-workers`, `serve-weight-store`) в SP1 только не должен сломаться. Его тесты должны проходить, а исправления общего кода (батч лёрнера, потоки, формат передачи, протокол модели) применяются и к нему. Новых возможностей в распределённом режиме SP1 не добавляет.

## 3. Критерии готовности

1. **Тесты.** Полный `pytest` (без `slow` и `gpu`) проходит на CPU одним процессом без зависаний. Тесты пишут файлы только в `tmp_path`.
2. **Контрактные тесты** по цепочке «настоящий цикл воркера → настоящий APPO» зелёные:
   - лёрнер воспроизводит log-prob и value воркера для четырёх ядер: без памяти, LSTM, GRU, окно внимания;
   - self-play с двумя агентами;
   - лига на трёх агентах, где встречаются все пары;
   - пошаговая игра: проигравший получает −1 на своём последнем переходе, флаги конца эпизода стоят у всех собирающих мест;
   - порядок действий при 12 компонентах `MultiDiscrete`/`Tuple`;
   - баланс мест ±5%;
   - eval модели с состоянием.
3. **Тесты «учится»:**
   - бандит и короткая цепочка решаются за секунды — на каждом прогоне;
   - крестики-нолики с маской и флагом «чей ход» дают ≥80% побед (greedy) против случайного игрока, делающего только легальные ходы, примерно за 3 минуты на 8-ядерном CPU — маркер `slow`.
4. **Видимость без WandB.**
   - Есть папка `runs/<name>/` с `config.resolved.yaml`, `logs/*.log` по каждому процессу, `metrics.jsonl`, `ratings.json` и `checkpoints/`.
   - В консоли виден периодический прогресс по каждому агенту.
5. **Жизненный цикл:**
   - бюджет `training.total_timesteps` соблюдается;
   - при нормальном завершении сохраняется финальный чекпоинт каждого агента, код выхода 0;
   - смерть воркера или лёрнера даёт сообщение с именем процесса и путём к его логу, ненулевой код и никаких зависаний;
   - после SIGTERM главному процессу все дочерние завершаются за ≤10 с.
6. **Скорость.** Throughput монотонно растёт при переходе от 1 к 2 и 4 воркерам на крестиках-ноликах. Замеры «до» и «после» записаны в `docs/benchmarks.md`.
7. **Документация.** Команды из README работают дословно. README и раздел статуса в CLAUDE.md описывают реальное состояние.
8. **GPU.** Всё, что требует GPU, помечено маркером `gpu` и перечислено в `docs/GPU_CHECKS.md` с инструкцией прогона.

## 4. Принципы

- **Обратной совместимости нет.** Внешних пользователей нет. Форматы конфига, чекпоинтов и папок меняются свободно, примеры и тесты обновляются в том же блоке.
- **TDD.** В каждом блоке сначала пишутся падающие тесты (контрактные и юнит), потом реализация.
- **Тесты через реальных производителей данных.** Тест, который собирает чанк вручную, не считается проверкой контракта воркер ↔ лёрнер.
- **Между процессами — только numpy и примитивы.** Через `mp.Queue` тензоры torch не передаются: их передача через дескрипторы shared memory роняет получателя, когда отправитель завершился (R6-02).
- **Язык.** Код, комментарии и docstring пишутся на английском, как в остальном репозитории. Документы в `docs/` — на русском.

### Блок 1. Протокол модели (`PolicyModel`)

Заменяет `ActorCriticNetwork` с встроенным `recurrent_type` и все ветки `if is_recurrent` / `lstm_hidden` в воркере, APPO, eval, BC и kickstart (R1-01, R1-02, R2-01, R4-11, ET-10, ET-17).

**Состояние.** `State` — дерево тензоров (`Tensor | tuple | list | dict | None`). У каждого листа батч-измерение — `dim 0`. Утилиты лежат в `colosseum/networks/state.py`:
- `tree_map`;
- `slice_batch(state, idx)` — индекс или список индексов, батч-измерение сохраняется;
- `cat_batch(states)`;
- `where_done(done_mask, reset_state, state)`;
- `state_to_numpy` / `state_from_numpy` для передачи между процессами.

**Интерфейс** (`colosseum/networks/model.py`):

```python
class StepOutput(NamedTuple):
    dist: Distribution          # batch [B]
    value: Tensor               # [B]
    state: State

class UnrollOutput(NamedTuple):
    dist: Distribution          # batch [T*B], time-major flatten
    value: Tensor               # [T*B], time-major flatten

class PolicyModel(nn.Module, ABC):
    def initial_state(self, batch_size: int, device="cpu") -> State:
        return None                                   # stateless by default

    @abstractmethod
    def step(self, obs: Tensor, state: State,
             action_mask: Tensor | None = None) -> StepOutput: ...

    def unroll(self, obs: Tensor, state0: State, dones: Tensor,
               action_mask: Tensor | None = None) -> UnrollOutput:
        """obs [T,B,...], dones [T,B] bool: dones[t] = episode ended AFTER step t,
        so the state is reset before step t+1. Default: loop over step() with
        reset_state(); correct for any model. Models may override with a fast path."""

    def reset_state(self, state: State, done: Tensor) -> State:
        """done [B] bool. Default: replace rows where done with initial_state rows."""

    @property
    def is_stateful(self) -> bool:                    # initial_state(1) is not None
        ...
```

Хелпер `act(model, obs, state, action_mask, deterministic) -> (actions, log_probs, values, new_state)` вызывает `step`, затем `sample()` или `mode()`, затем `log_prob`. Им пользуются воркер и eval.

**`ComposedModel(encoder, core, policy_head, value_head)`** — сборка по умолчанию:
- `encoder(obs) -> latent [B, D]`;
- `core.step(latent, state) -> (features [B, O], state)`;
- `policy_head(features) -> Distribution` (маска применяется через `dist.apply_mask`);
- `value_head(features) -> [B]`.

**Протокол ядра** (`colosseum/networks/cores.py`):

```python
class Core(nn.Module, ABC):
    output_dim: int
    def initial_state(self, batch_size, device="cpu") -> State: ...
    def step(self, x: Tensor, state: State) -> tuple[Tensor, State]: ...
    def unroll(self, x: Tensor, state0: State, dones: Tensor) -> Tensor:  # [T,B,O]; default loop
        ...
```

**Ядра в комплекте:**

| Ядро | Описание | Состояние |
|---|---|---|
| `NoCore` | identity, `output_dim = input_dim` | `None` |
| `LSTMCore(hidden_size, num_layers=1)` | LSTM | `{"h": [B,L,H], "c": [B,L,H]}`, внутри транспонируется в формат `nn.LSTM` |
| `GRUCore(hidden_size, num_layers=1)` | GRU | `{"h": [B,L,H]}` |
| `WindowAttentionCore(d_model, window, num_heads, num_layers=1)` | причинное внимание текущего токена на последние `window` латентов, реализация в духе GTrXL-lite без гейтинга | `{"mem": [B,window,d_model], "len": [B] int}`, сброс обнуляет `len`, внимание маскируется по `len` |

Быстрые пути `unroll` (cuDNN, маска внимания по всей последовательности) — в SP6. В SP1 у всех ядер корректный, пусть и медленный, цикл.

**Монолитная модель.** Пользователь может наследовать `PolicyModel` напрямую. Например, трансформер над сущностями с выходом по юнитам: этот кейс разблокирует SP2.

**Конфиг** `networks` (поля `recurrent_type`, `recurrent_hidden_size`, `recurrent_num_layers` удаляются):

```yaml
networks:
  model_class: null                 # монолитная модель; если задано — остальные *_class не нужны
  encoder_class: my_game.nets.Encoder
  core: {class: colosseum.networks.cores.LSTMCore, kwargs: {hidden_size: 128}}   # или null
  policy_class: my_game.nets.Policy
  value_class: my_game.nets.Value
  kwargs: {}                        # общие kwargs конструкторов (как сейчас)
```

**Сборка (`build_model` вместо `build_network`):**
- Если конструктор головы принимает параметр `in_dim`, `build_model` передаёт туда `core.output_dim`.
- Если не принимает, `validate_config` ловит несовпадение размеров пробным forward и выдаёт понятную ошибку.
- `validate_config` прогоняет `step` и `unroll` на dummy-данных и проверяет:
  - форму `value` `[B]`;
  - батч-измерение у всех листов состояния;
  - размер маски.

**Миграция.** Ветки `is_recurrent`, `lstm_hidden`, `evaluate_actions_recurrent` и `initial_hidden` удаляются. Примеры, тестовые хелперы и `BasePolicy`/`BaseValue`/`BaseEncoder` остаются как базовые классы частей `ComposedModel`.

### Блок 2. Поток данных

- **Потоки torch** (R2-04, R6-04):
  - `rollout.torch_threads: int = 1`. Воркер в самом начале процесса вызывает `torch.set_num_threads(n)` и `torch.set_num_interop_threads(1)`. Дочерние процессы `SubprocessVectorEnv` ставят `OMP_NUM_THREADS=1` и `torch.set_num_threads(1)`;
  - `learner.torch_threads: int | None = None`. Для CPU-лёрнера `None` означает `max(1, (cpu_count − num_workers·rollout.torch_threads) // num_learners)`, для CUDA — 2.
- **Передача между процессами** (R6-02, R3-07):
  - `TrajectoryChunk.to_payload() -> dict` из numpy-массивов, примитивов и состояния через `state_to_numpy`; обратно — `from_payload`;
  - `WeightPayload` хранит `state_dict` как `dict[str, np.ndarray]`;
  - всё, что идёт через `mp.Queue`: чанки, веса, чекпоинты, команды, результаты, метрики — только в payload-форме;
  - gRPC-сериализация в SP1 работает поверх того же payload. Формат на проводе меняется в SP5.
- **Веса, newest-wins** (R2-05, R3-10):
  - у каждого агента и воркера своя `mp.Queue(maxsize=1)`;
  - лёрнер публикует так: `put_nowait`; при `Full` делает `get_nowait` (выбрасывает старое, игнорируя `Empty`), затем `put_nowait` (игнорируя `Full` при гонке);
  - воркер вычитывает очередь до последнего элемента.
- **Батч лёрнера** (R3-11, R1-11):
  - `_collect_chunks` блокируется, пока не наберёт ровно `learner.batch_chunks` чанков;
  - ожидает частями по 0.5 с и проверяет `stop_event`;
  - обучения на неполном батче нет.
- **Общий бюджет** (R6-11, R1-11):
  - `training.total_timesteps` — суммарные шаги сред по всем воркерам;
  - счётчик — общий `mp.Value("q")`; воркеры прибавляют к нему накопленное локально примерно раз в 0.5 с;
  - главный процесс выставляет `stop_event`, когда счётчик ≥ бюджета;
  - поле `progress = min(1, counter / total_timesteps)` передаётся алгоритму через `algorithm.set_progress(p)` перед каждым шагом обучения;
  - LR-schedule считается от `progress`. Затухание kickstart остаётся в шагах обучения.
  - В распределённом режиме общего счётчика нет: `progress = consumed_samples / total_timesteps` на лёрнере (задокументировать).
- **Буферы без потерь при смене матча** (R2-12):
  - буферы принадлежат агенту, а не месту;
  - когда место на границе эпизода переходит к другому агенту или перестаёт собирать данные, его частичный буфер (последний переход уже закрыт флагом `done`) «паркуется» в пул воркера для этого агента;
  - следующее место, начинающее собирать данные для этого агента, сначала берёт припаркованный буфер;
  - чанк остаётся последовательностью переходов одного агента с границами эпизодов. Состояние модели сбрасывается на `done`, поэтому эпизоды из разных сред в одном чанке корректны.
- **Версии политики.** `behavior_policy_version` чанка — версия весов на момент его *первого* перехода. Лёрнер логирует `policy_lag = current_version − behavior_version`: среднее и максимум по батчу. Фильтрация по лагу — в SP5.

### Блок 3. Переходы в воркере

Решает потерю наград и флагов `done` у неактивных мест (R1-22, R2-02, ET-01), лишний bootstrap-forward (R2-11, R1-04 частично), продвижение состояния на чужих ходах (ET-17) и затирание исходов (R4-03, ET-04, R2-08).

**Состояние места** `SlotTrack` для каждой пары (среда, место): ссылка на буфер агента, флаг «есть открытый переход», накопитель `pending_reward` (награды до первого хода места в эпизоде), состояние модели.

**Буферы.** У каждого агента в воркере свой пул буферов. Каждое собирающее место держит один буфер эксклюзивно, поэтому два места одного агента в одной среде (latest против latest) пишут в разные буферы. Свободные буферы — частичные, припаркованные по правилам блока 2, или новые.

**Формат чанка** (`core/types.py`):
- поле `lstm_hidden` заменяется на `initial_state: State` — состояние модели на момент первого перехода чанка, листья формы `[1, ...]`. Для моделей без состояния — `None`;
- `dones[t] = terminated or truncated` — переход t последний в эпизоде. При truncation награда уже содержит `γ·V(final_obs)`;
- `bootstrap_value` — значение следующего хода места или 0, если последний переход терминальный;
- `behavior_policy_version`, `action_masks` и остальные поля остаются;
- через процессы чанк ходит только как `to_payload()` / `from_payload()`.

**Шаг цикла:**
1. **Кто ходит.** Ходящие места определяются по `info["active"]`; если флага нет, ходят все. Подробная семантика флага и неходящих мест — в SP2.
2. **Инференс** только для ходящих мест, сгруппированных по (агент, сеть). Остальные места получают действие по умолчанию из `ActionSpec` (нули), их состояние модели не меняется.
3. **Ходящее собирающее место:**
   - если открыт предыдущий переход: при полном буфере (T переходов) запечатать чанк с `bootstrap_value = value` из этого инференса, при неполном — просто закрыть переход;
   - затем открыть новый переход `(obs, action, log_prob, value, mask, reward=pending_reward, done=False)` и обнулить `pending_reward`.
4. **После `env.step`:** награда каждого собирающего места добавляется к его открытому переходу, а если перехода нет — к `pending_reward`.
5. **Конец эпизода** (`terminated or truncated` у среды): для каждого собирающего места:
   - открытый переход получает `done=True`;
   - при **truncation** к его награде добавляется `γ·V(final_obs)`. `V` считается моделью места по `infos[...]["terminal_observation"]` с текущим состоянием места; один forward на эпизод, только при truncation (R1-03, R2-09);
   - если буфер полон — чанк запечатывается (bootstrap не используется, так как переход терминальный).
   - Затем:
     - отправляется результат матча;
     - сбрасывается состояние модели мест;
     - применяется отложенное назначение матча с парковкой буферов (блок 2).
6. **`bootstrap_value` чанка** всегда либо значение из следующего хода места, либо 0 для терминального перехода. Отдельного bootstrap-forward больше нет.

**Маски** (R1-13, ET-08). Если у неходящего места строка маски не содержит допустимых действий, она заменяется на «всё разрешено» (его действие игнорируется и не записывается). У ходящего места такая строка вызывает `EnvContractError` с указанием среды, места и шага.

**Результат матча:**

```python
@dataclass
class SeatResult:
    seat: int
    agent_id: str
    network_id: str          # "latest" | "ckpt_v…"
    outcome: float           # из core/outcomes.py: rank/outcome среды или суммарная награда
    reward: float            # суммарная награда места за эпизод
    rank: int | None

@dataclass
class MatchResult:
    match_id: str
    seats: list[SeatResult]
    episode_length: int
```

**Утечка `info` после auto-reset** (R2-14). Маска и `active` для первого хода нового эпизода берутся из `reset`-info, а не из терминального `info` прошлого эпизода.

### Блок 4. Алгоритм

- **APPO на `PolicyModel`.** Обучение всегда идёт через `model.unroll` с `state0 = cat_batch(chunk.initial_state…)`. Для моделей без состояния `unroll` по умолчанию эквивалентен батчу `step`. Отдельного «рекуррентного пути» больше нет.
- **λ в V-trace** (R1-12): `AlgorithmConfig.vtrace_lambda: float = 1.0` даёт `c_t = λ·min(c̄, ρ_t)`. Поле `gae_lambda` удаляется. Упоминания GAE в документации исправляются.
- **Нормализация наблюдений** (R1-08):
  - `NormalizeObs` получает явный `update(obs_batch)`, forward статистику не меняет;
  - APPO вызывает `model.update_normalizers(obs)` один раз за шаг обучения, до эпох;
  - статистика лежит в буферах модели и уходит к воркерам вместе с весами.
- **Маски.** `CategoricalDist.kl_divergence` при маске считает KL только по легальным действиям, без NaN и inf (R1-13).
- **Kickstart** (R1-14, R1-02):
  - `training.kickstart_kl: "forward" | "reverse" = "forward"`, где forward = KL(teacher‖student);
  - учитель — тоже `PolicyModel`, прогоняется через `unroll` с маской из чанка;
  - распределение студента берётся из основного forward, без лишнего прохода;
  - учитель в SP1 по-прежнему строится из конфига студента. Отдельный конфиг учителя — SP3.
- **BC** (R1-05, R1-02):
  - формат данных: `observations`, `actions` и необязательные `action_masks`, `dones`;
  - лосс выбирается по типу распределения: `−log_prob` для Categorical, DiagGaussian и Composite. MSE по среднему удаляется;
  - маски применяются;
  - float-действия при дискретном пространстве дают ошибку;
  - для модели с состоянием BC идёт через `unroll` по непрерывным отрезкам длины `bc.seq_len` (CLI `--seq-len`, по умолчанию 64) со сбросом по `dones`. Если `dones` нет, датасет считается одним эпизодом и выдаётся предупреждение.
- **Порядок компонент действий** (R2-03, ET-07). `ActionSpec` нумерует компоненты `Tuple` и `MultiDiscrete` по индексу, а не сортировкой строк. Компоненты `Dict` идут в порядке `space.spaces`. Тест: 12 компонент, среда получает каждому юниту именно его действие.
- **Состояние обучения и resume** (R1-07, R3-19, R3-20):
  - `BaseAlgorithm.state_dict() / load_state_dict()` — оптимизатор, LR-scheduler, GradScaler, шаг kickstart, `policy_version`, `consumed_samples`;
  - чекпоинт хранит `model.pt`, `trainer_state.pt` (глубокая копия, все тензоры через `.detach().cpu().clone()`) и `meta.json`;
  - в `meta.json`: агент, версия, время, хеш итогового конфига, секция `networks` агента.
- **Метрики APPO** дополняются: `explained_variance`, `grad_norm` (до клиппинга), `rho_mean`, `rho_clip_frac`, `policy_lag_mean`, `policy_lag_max`, `lr`.

### Блок 5. Лига (минимальные исправления на текущей модели)

- **Владельцы сред** (R4-01, R5-15, R6-03). `Coordinator.generate_match_configs(num_envs, env_offset)` больше не принимает агента:
  - глобальный индекс среды `g = env_offset + e`;
  - владелец `agents[(g + refresh_round) % n_trainable]`;
  - матч генерируется для владельца.
  Это работает и в `self_play`, и в `league`.
- **Self-play владельца.** Семантика `latest_prob` прежняя: в первом слоте владелец latest с `collect=True`; в остальных latest того же агента (`collect=True`) с вероятностью `latest_prob`, иначе его случайный чекпоинт (`collect=False`).
- **Арена на N игроков** (R4-09, ET-16). Владелец плюс N−1 соперник, выбранные PFSP из других обучаемых агентов с возвращением. Все слоты latest с `collect=True`. Доля solo/arena задаётся `self_play_ratio`, как сейчас.
- **Перемешивание мест** (R4-02, ET-15). `self_play.shuffle_seats: bool = true`: слоты матча перемешиваются случайной перестановкой.
- **Рейтинги** (R4-04, ET-03, R4-08, G2 из исследования):
  - пары мест с разными базовыми агентами сравниваются по `outcome`: больше — 1, равно — 0.5, меньше — 0;
  - `WinRateTracker` хранит дробные суммы, `int(x*2)` убирается;
  - ELO обновляется по каждой такой паре с `K / (N−1)`;
  - пары одного агента в ELO не идут;
  - отдельная метрика `wr_vs_past[agent]` — доля побед latest над своими чекпоинтами. Это сигнал прогресса в self-play (R4-07).
- **Чекпоинты** (R4-06, R6-05, R6-06, R3-06):
  - `CheckpointManager(base_dir = run_dir/checkpoints)` сканирует только свою папку;
  - путь при удалении строится как `base_dir/agent/ckpt_id`, путь из `meta.json` не используется;
  - запись атомарная: `.tmp-<id>/`, затем `os.replace`;
  - id `ckpt_v{policy_version}`, версии продолжаются после resume;
  - пул FIFO `pool_size` (top-k и закрепление — SP3).
- **Финальный чекпоинт** (R3-07). При остановке каждый лёрнер отправляет финальный снимок блокирующим `put` с таймаутом 30 с. Главный процесс сохраняет его до завершения дочерних процессов.
- **Пропавший чекпоинт соперника** (R4-19, R2-06): слот переходит на latest с `collect=True` и выдаётся предупреждение. Набор отправленных воркеру чекпоинтов помечается только после успешного `put`.
- **`resume_from`:**
  - путь к папке чекпоинта — модель и `trainer_state`;
  - путь к папке прошлого запуска — каждый агент берёт свой последний чекпоинт;
  - путь к `.pt` (например, выход BC) — только веса, для всех агентов; если архитектура не совпадает — понятная ошибка.
  Warm start на каждого агента — SP3.

### Блок 6. Наблюдаемость, конфиг, жизненный цикл

**Папка запуска.** Новая секция конфига `run: {name: str | null, dir: "runs"}`. По умолчанию `name = <config_stem>-<YYYYmmdd-HHMMSS>`. Поле `checkpoint.dir` удаляется, чекпоинты всегда лежат в папке запуска. Содержимое:

```
runs/<name>/
  config.resolved.yaml     # после override и слияния агентов
  logs/main.log  logs/learner-<agent>.log  logs/worker-<i>.log
  metrics.jsonl
  ratings.json             # периодически и в конце
  checkpoints/<agent>/ckpt_v…/{model.pt, trainer_state.pt, meta.json}
```

**Логирование** (R5-01, R3-16). Функция `setup_process_logging(run_dir, process_name)` вызывается первой строкой в каждом process target:
- в файл пишется уровень INFO;
- в консоль у детей — WARNING, у главного процесса — INFO.

**`metrics.jsonl`.** Одна JSON-строка на запись `{"ts", "kind", "agent"?, ...}`. Виды записей:
- `train` — метрики APPO, с частотой `metrics.log_interval` шагов;
- `episodes` — по агенту за интервал: средние награда и длина, W/D/L против latest, прошлых чекпоинтов и арены;
- `ratings` — ELO, матрица win-rate, `wr_vs_past`;
- `system` — шаги сред всего и в секунду, шаги обучения в секунду по лёрнерам, глубины очередей, число припаркованных буферов.

Пишет только главный процесс, данные получает из `metrics_queue` и `results_queue`.

**Консоль.** Каждые `metrics.console_interval_sec` (по умолчанию 10) выводится одна строка на агента: шаг, доля бюджета, FPS, loss, энтропия, средняя награда, `wr_vs_past` или win-rate в арене.

**WandB** (R5-02). Остаётся необязательным (extra `wandb`). Один run, на каждого агента `wandb.define_metric(f"{agent}/*", step_metric=f"{agent}/train_step")`. Рейтинги и system-метрики идут с шагом `env_steps`. Источник правды — `metrics.jsonl`.

**Конфиг** (R5-07, R5-08, R4-16, R5, R3-27):
- `model_config = ConfigDict(extra="forbid")` во всех моделях;
- override агента (`agents.<id>.networks|algorithm|learner`) задаётся частичным словарём и глубоко сливается с глобальной секцией до валидации;
- один `apply_overrides(config_dict, overrides)` в `core/config.py` для `train`, `run-learner`, `run-workers` и `validate`;
- значения `--set` разбираются через `yaml.safe_load` (`null`, числа, списки), неизвестный путь — ошибка;
- сиды ставятся после override;
- `validate` проверяет `env.num_players == env().num_players` и протокол модели (блок 1).

**CLI** (R5-19):
- `colosseum` вставляет текущую папку в начало `sys.path`;
- `train` печатает путь к папке запуска;
- коды выхода: 0 — нормальное завершение, 1 — упал дочерний процесс или ошибка конфига, 130 — SIGINT, 143 — SIGTERM.

**Процессы** (R3-08, R3-09, R3-17, R6-07):
- дети игнорируют SIGINT и останавливаются через `stop_event`;
- главный процесс ловит SIGINT/SIGTERM, ставит `stop_event`, ждёт до 10 с и убивает оставшихся;
- монитор замечает ребёнка с ненулевым `exitcode`, останавливает всех и завершает работу с кодом 1 и сообщением `"<process> died (exit N), see runs/<name>/logs/<process>.log"`;
- нормальное завершение (бюджет исчерпан) не логируется как «unexpected» (R6-11).

### Блок 7. Eval

- Eval построен на `PolicyModel.step` и `act` с состоянием каждого места, поэтому работает с любой моделью (R4-11, ET-10).
- `-a name=path`, где путь — папка чекпоинта или `.pt`. Если у чекпоинта есть `meta.json` с `networks`, модель строится по нему. Так можно сравнивать разные архитектуры (R4-12 частично). Для `.pt` берётся `--config`.
- `--num-matches` — число матчей **на пару** (R4-13, R6-10).
- Места ротируются: каждый агент поровну играет на каждом месте.
- **Вывод для пары:**
  - W/D/L;
  - win-rate с интервалом Уилсона;
  - счёт (W + ½D)/n с интервалом Уилсона по счёту (приближение, задокументировать);
  - разбивка по местам.
  Отражённые строки считаются из той же статистики, без дублирования.
- **Соло** (один агент): средний счёт и награда с 95% интервалом (нормальное приближение) (ET-11).
- `--output result.json` — машинно-читаемый результат.

## 6. Тестирование

| Уровень | Что проверяет | Где |
|---|---|---|
| Юнит | V-trace с λ против эталонной реализации; утилиты `State`; маски и KL; порядок компонент `ActionSpec`; попарные рейтинги; слияние конфига, `extra="forbid"`, парсер `--set`; атомарная запись и удаление чекпоинтов | `tests/unit/…` |
| Контракт | Настоящий цикл воркера в процессе теста (функция-итерация воркера на игрушечных средах, очереди-заглушки) → `TrajectoryChunk` → `from_payload` → настоящий APPO. Проверяется: совпадение log-prob и value для 4 ядер; награды и `done` в пошаговой игре; 12 юнитов; парковка буферов без потерь; исходы по местам; отсутствие bootstrap-forward | `tests/contract/…` |
| Интеграция | Короткие `train` через `spawn`: self-play с 2 агентами до конца бюджета; лига на 3 агентах (все пары, баланс мест); resume продолжает версии и LR; убийство воркера → код 1 и сообщение; SIGTERM → дети завершены ≤10 с; содержимое `runs/<name>/`; финальный чекпоинт | `tests/integration/…` |
| «Учится» | Бандит и цепочка (быстро); крестики-нолики ≥80% (`slow`) | `tests/learning/…` |
| GPU | AMP, `pin_memory`, перенос устройств (`gpu`) | рядом с соответствующими юнит-тестами |

Чтобы контрактные тесты не требовали процессов, тело цикла воркера выносится в класс `RolloutLoop` с методами `step()` и `close()`. `rollout_worker_process` превращается в тонкую обёртку: процесс, сигналы, очереди. Существующие тесты переносятся в новую структуру или удаляются, если проверяют удалённое поведение. Репро-скрипты из `review/repro/`, где применимо, превращаются в тесты.

## 8. Принятые решения и риски

| Решение / риск | Обоснование / смягчение |
|---|---|
| Truncation через добавку `γ·V(final_obs)` к награде на воркере, а не bootstrap на лёрнере | Минимальное изменение формата V-trace. Значение берётся из сети поведения (небольшая устарелость). Перенос на лёрнер — в SP2 вместе с моделью мест |
| Буферы принадлежат агенту и паркуются | Нет потерь данных и паддинга. Корректно, так как каждый эпизод в чанке начинается после `done` |
| `unroll` по умолчанию — цикл `step` | Корректно для любой модели, но медленно для LSTM/внимания. Быстрые пути — SP6. Для SP1 скорость лёрнера не критерий |
| Большой рефакторинг воркера (блоки 1–3) | Контрактные тесты пишутся до изменений. Выделение `RolloutLoop` делает цикл тестируемым без процессов |
| Числа в `progress` и бюджете отличаются в распределённом режиме | Документируется. Единая семантика появится с хабом в SP5 |
| Интервал Уилсона по счёту с ничьими — приближение | Задокументировать. Строгий отбор (Bradley–Terry с bootstrap) — в SP4 |
| `wandb` становится необязательной зависимостью | Источник правды — `metrics.jsonl`. WandB — только просмотрщик |
