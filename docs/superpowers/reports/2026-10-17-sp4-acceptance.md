### Решения волны исправлений

Решения контроллера для волны — из её брифа ([`fix-wave-brief.md`](2026-10-17-sp4-review/fix-wave-brief.md), дословно):

- **A-M3 (startup race).** A training worker, local or distributed, never plays a trainable agent's `latest` seats before it has received that agent's first weights from the learner.
  - At startup the worker waits for the first weight payload of every trainable agent it serves.
  - The wait is in short slices and stops on `stop_event`.
  - It logs one INFO line if it waits longer than a few seconds.
  - Today the worker plays its own factory weights, which are random, as version 0 until the first sync (up to `rollout.weight_sync_interval_sec`). With `init.from` or a resume, those games are journaled as `v0` / the resumed version and mix random-weight games into that bucket's rating.
  - In-process loops and unit tests that never push weights must keep working. Use an explicit option, default off in `RolloutLoop`, on in the worker processes; or an equivalent design. Say which one you chose.
  - Needs a test showing that no match is played or journaled before the first weights arrive.
- **A-M7 (SP3 compatibility of the snapshot cap).** When `checkpoint.max_snapshots` is not set in the config and `keep_last` is greater than 100, the cap becomes `keep_last`, with one INFO line.
  - The case also covers an SP2 `pool_size` translated to `keep_last`.
  - An explicit `max_snapshots` below `keep_last` stays a `ConfigError`.
  - Needs a test with an SP3-form config that has `keep_last: 150`.
- **B-I1 (one-team games).** An empty field is allowed in two cases.
  - In `colosseum tournament`, when every chosen layout has one team. The modes are gauntlet, halving and select. Round-robin already refuses one-team layouts (C4).
  - In the pulse, when no planned layout has two or more teams.
  - The error text for a real two-team empty field stays as it is.
  - Needs one test per path, plus one ARENA_GUIDE sentence.
- **B-M8 (round-robin role groups).** Mixed role groups in one round-robin table are a `ConfigError` that lists the groups. This follows spec block 3 («Смешанные группы в одной таблице — ConfigError с перечнем групп»).
  - A participant with no playable pair gets `score: null`, not 0.0.

- **C-I1 (live dashboard filters).** In live mode the page keeps its own layout choice. It does not send `layout` in its refresh query and then rebuild the select from the answer. The matrix section gets an agent select that drives `api/matrix?agent=`, and drives the score cross-play too (T7.1 deferred).
  - Needs a live-page DOM test: headless Chrome, as in `_dom`. It must show that a second layout and another agent stay reachable after a refresh.
  - The ARENA_GUIDE line about the agent filter must describe the page as it is after the fix.
- **C-M4 (static report).** `colosseum report` isolates sections, as the dashboard does. A failing section gets a `{"notes": ["This section failed: …"]}` placeholder, the page is still written, and the command exits 1 with a message naming the failed sections. The page is useful, and the failure must not look like success.
- **C-M2 (report memory).** `MetricsTail` keeps bounded memory over a run of any length.
  - Thin each (kind, agent) series by its counter on ingest, using stride doubling: the order and counter keys stay as they are, and the page's own size limits stay.
  - Read the file in fixed-size chunks.
  - The docstring states the bound.
- **A-M4 (compact `best`).** The `ratings` record's `best` is the best stored snapshot, as spec block 2 says («лучшего снимка»): versions > 0 that are stored. If the live thread cannot know the stored set cheaply, restrict `best` to versions > 0 and call it "best version" in the docs. Say which.
- **B-M2 (dead tournament worker).** The engine checks `first_failure` once per loop iteration, not only on an empty queue. On a failure it sets `stop` first, and it keeps journaling the `done` blocks that arrive while it looks for the typed error, bounded by `STOP_GRACE_SEC`.
- **B-M6 (snapshot link dir).** In a new tournament, where nothing references `snapshots/` yet, the dir is emptied before linking. A reused link dir is never trusted by its path alone.

   `run` returns before its first step.

   - Cost if wrong: one env reset during shutdown, inside `SHUTDOWN_GRACE_SEC` for any reasonable env.
3. **A-M3: a worker now waits for as long as its learner takes to start.**
   - Why: this is the ruling. A learner that dies before pushing is a dead child, and the supervisor sets
     `stop_event`. A distributed worker whose learner never publishes waits until stopped, with the INFO line.
   - Cost if wrong: a distributed worker started long before its learner idles visibly instead of playing random
     weights.
4. **A-M4: the real stored set is used** (the checkpoint manager's index in the main process), so the docs say "best
   stored snapshot", not "best version". `stored=None`, a hub without a source, falls back to versions > 0.
   - Cost if wrong: none for the metrics. The WandB keys `ratings/bt/<agent>/<layout>/best/*` are now missing in a
     layout until a stored snapshot is rated.
5. **A-M7: the raised cap is stored in the validated config**, so `config.resolved.yaml` shows `max_snapshots: 150`
   as an explicit value.
   - Why: one INFO line per config, not one per re-validation.
   - Cost if wrong: a later run that reuses that resolved file with a lower `keep_last` keeps the cap at 150 (a
     higher cap, harmless).
6. **M8: the post-write existence check is only for pinning**, not for unpinning. After an unpin, an eviction is the
   intended effect.
   - Cost if wrong: none.
7. **M1: beyond the wording, the thread records its current operation** (a string attribute written by the thread
   only), so the WARNING can name compaction, opening, sizes or the live-table feed.
   - Cost if wrong: one attribute write per operation.

Часть FW-B ([`fix-wave-B-report.md`](2026-10-17-sp4-review/fix-wave-B-report.md)):

- **M3: an evicted snapshot at the start is a ConfigError, not a skip** — что: `link` raises «... was evicted by the run while the tournament started; rerun» — почему: the selection the user asked for never changes silently (a skipped `--field` snapshot would change the field, a skipped candidate the ranking), nothing is written before the links (`tournament.yaml` comes after them, and B-M6 makes a rerun start from an empty `snapshots/`), and the race window is seconds — цена ошибки: a user with very aggressive retention reruns once more; a skip could be added later for candidates only.

7. **Состояние лиги (T3.2):** строки PFSP снимков, вытесненных после последнего такта убитого (SIGKILL) родителя, переживают resume; `forgotten` растёт без предела (требование спеки, мало); нет сквозных тестов импорта, испорченного `league_state.json`, пути ERROR при записи.

9. **Турнир:** два одновременных старта одного `--name` не исключены (B-M7); после падения воркера блоки, которые соседи доиграли позже `STOP_GRACE_SEC`, не попадают в журнал (переигрываются при продолжении); нетипизированный ValueError halving (недостижим из CLI); (T−1)! порядков на состав в многокомандных асимметричных раскладках; соседство в FFA не сбалансировано (циклические сдвиги по спеке; описано); без `-c` конфиг первого запуска читается дважды; ошибка в незапланированном повторном эпизоде называет uid последнего состава; мёртвый `or '-'` в `_drop`.
10. **eval / игроки:** docstring'и `MatchRunner.set_next_lineup` / `lineup()` молчат о `snapshot_fallback=False`; повторное использование `fixed.frozen` в `load_player` не отмечает архитектуру проверенной (лишняя проверка стоит только времени).
11. **Отчёт:** потолки раскладок `score` применяются до фильтра агента; подгонка рейтингов читает журнал заново, а матрица и якоря — кэшированную таблицу (разделы могут расходиться на несколько игр); раздел турниров не ограничен по числу (C-M5; описано в ARENA_GUIDE §7); раздел соперников не рисует доли отдельных якорей; правило прохода `scripts/measure_bt_cost.py` записано прямо в коде и не покрыто тестом (C-M10).
12. **Бенчмарк:** `CounterSampler` пишет глубину −1 и для «записи `system` ещё нет», и для «неизвестно»; под `--tree` сводка нагрузки и классификация узкого места берут константы этой ветки; нет теста ValueError `run_one` на неизвестные часы; исключение потока-сэмплера всплывает вдали от сообщения.
13. **Тесты, косметика:** нет тестов срезанной массы при `unit_trace: geo_mean` и для пачки без ACT-слотов; `_diagnostics` берёт `exp` от `trace_log_rho` в его собственном типе (уровень округления под AMP); тест ленивого пула проверяет только метки версий.
