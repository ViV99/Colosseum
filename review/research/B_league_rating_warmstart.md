## 0. Резюме

### 0.1. Главные выводы (коротко)

1. **Лига AlphaStar в чистом виде не масштабируется вниз.** TStarBot-X (1/30 ресурсов AlphaStar, 144 V100, 57 дней) прямо пишет, что "faithful reimplementation" AlphaStar при малых ресурсах не работает: exploiters либо слабеют, либо периоды между снапшотами занимают >10 дней. Рабочая "малая" версия: **смесь SP + PFSP по пулу снапшотов + (опционально) 1 main exploiter на main agent + наследование (не сброс с нуля) для exploiters**. Абляция AlphaStar: exploiters дают +284 Elo (1540 -> 1824) и RPP 6% -> 62%, но чистый self-play почти не уступает по Elo, зато сильно забывает (min win-rate против прошлых версий 46% против 71% у смеси SP+PFSP) [V].
2. **Победители Kaggle-симуляций редко используют полноценную лигу.** Реально встречается: latest 70-85% + прошлые чекпоинты 15-30% (OpenAI Five 80/20; Boey Lux S3 75/25; Kiwis 75/25; SaltyFish GRF 70%), PFSP у RLIAYN (Lux S1, 2-е) и Boey, локальная лига/ELO для выбора сабмита у WeKick, Raw Beast, Hungry Geese 3rd. Общий знаменатель всех RL-победителей: **frozen teacher + KL** (Toad Brigade, FLG, Flat Neurons, Frog Parade, EcoBangBang, TamakEri) [V, по writeups].
3. **Для большинства игр RL вообще не выигрывает.** Halite IV, Kore 2022, Lux S2, Battlecode, Pommerman: победили rules/поиск. RL выигрывал там, где есть (а) очень быстрый симулятор (Rust ~110k steps/s у Frog Parade, JAX ~80k SPS у Boey), (б) один центральный контроллер, (в) мало юнитов/короткое состояние. IL с реплеев лидеров - самый дешёвый путь в top-5 (Lux S1: 4, 5, 6, 11, 12 места; Lux S3: 3-е место).
4. **Online Elo - плохой инструмент отбора.** [SIM] При K=32 и 2000 играх шум разности рейтингов двух равных игроков 78 Elo против 7.8 у batch BT-MLE; с окном оппонентов "последние 10" онлайн-Elo сжимает шкалу (763-821 вместо истинных 990 Elo) и вдвое увеличивает RMSE. LMSYS ушли с online Elo на Bradley-Terry MLE именно поэтому. Рекомендация: **хранить сырые результаты матчей, считать batch BT-MLE + bootstrap по матчам, а онлайн-рейтинг (OpenSkill PlackettLuce) оставить только для дашборда и для приоритизации матчей**.
5. **Выбор лучшего чекпоинта - задача с winner's curse.** [SIM] Из 20 равных по силе кандидатов по 400 игр каждый выбранный "лучший" завышен в среднем на ~32 Elo, а вероятность выбрать истинно лучшего всего 4%. Лечение: независимый hold-out для финалистов, successive halving, симультанные доверительные интервалы, EMA-веса. Для двух сабмитов Kaggle: "последний на плато" часто надёжнее argmax шумных замеров.
6. **Нетранзитивность реальна и невидима для Elo.** [SIM] Добавление 10 клонов слабого агента подняло Elo "камня" с 95 до 300, а Nash average остался 0. Практика: gauntlet из замороженных референсов + несколько независимых линий (lineage), cross-play матрица, Nash average / alpha-Rank как диагностика, а не как основной рейтинг.
7. **Warm start: каноничный рецепт = BC -> value warmup -> RL с KL-якорем к BC с затуханием.** VPT: KL-коэффициент rho = 0.2, затухание 0.9995 за итерацию, lr 2e-5, value head инициализирован нулями, KL **заменяет** entropy bonus; без KL пришлось снижать lr в ~6.7 раз [V]. JSRL: случайный critic после pretrain actor заставляет политику "забыть" хорошее начало; critic warm-up при замороженном actor (100k шагов) это лечит [V].
8. **Расхождение с нашей документацией (важно).** В CLAUDE.md и в `src/colosseum/bc/kickstart.py` стоит `KL(student || teacher)`. Во всех трёх первоисточниках (Kickstarting, AlphaStar `rl.py`, VPT) используется направление **teacher -> student**, то есть `KL(teacher || student)` = cross-entropy(teacher, student) минус entropy(teacher) (forward KL, mode-covering) [V]. Рекомендуется сделать направление параметром (`forward` по умолчанию).
9. **Мониторинг лиги** - это не только WandB. Критичные метрики: payoff matrix с CI, win-rate против замороженных референсов, min win-rate против прошлых (forgetting), распределение выбора оппонентов, rho/ESS/policy lag для V-trace, вклад каждого loss-слагаемого (EcoBangBang нашёл так проблемный UPGO loss и вырос с 1400 до 1900+ LB). Neptune SaaS закрыт 2026-03-05 (данные удалены) [V], поэтому источник правды - свой SQLite/Parquet, трекер - только viewer.

## 1. Схемы лиг и self-play

### 1.1. AlphaStar league (Vinyals et al., Nature 2019) [V]

Три типа агентов; отличаются только распределением оппонентов, условием снапшота и вероятностью сброса.

| Роль | Оппоненты | Условие снапшота | Сброс |
|---|---|---|---|
| Main agent (MA) | 35% self-play, 50% PFSP по всем прошлым игрокам лиги, 15% PFSP против "забытых" main и прошлых main exploiters (если таких нет - в self-play) | каждые ~2e9 шагов | никогда |
| Main exploiter (ME) | только текущие main agents; если P(win) < 20% - в 50% случаев PFSP f_var по прошлым снапшотам main | win-rate > 70% против всех main, либо таймаут ~4e9 шагов | всегда на supervised-параметры |
| League exploiter (LE) | PFSP по всей лиге | win-rate > 70% против всей лиги, либо таймаут ~2e9 | с вероятностью 25% на supervised |

Показатели степени 2e9/4e9 в извлечённом PDF Nature повреждены; значения подтверждены независимо в TStarBot-X (раздел 4.5) и в реимплементации DI-engine (`starcraft_player.py`).

**PFSP**: P(B) = f(P[A бьёт B]) / sum_C f(P[A бьёт C]), где `f_hard(x) = (1-x)^p` (по умолчанию; сглаженная аппроксимация max-min), `f_var(x) = x(1-x)` (оппоненты своего уровня; для exploiters и "struggling" main). Конкретное p в статье не указано [не подтверждено для оригинала]; реимплементации и pseudocode используют `squared` = (1-x)^2, `linear` = 1-x, `linear_capped` = min(0.5, 1-x); при нулевой сумме - uniform.

Из pseudocode (`multiagent.py`, supplement) [V]:
- win-rate по паре ведётся с экспоненциальным забыванием `decay = 0.99`;
- в ветке self-play у main: если `payoff[self, opponent] <= 0.3` (оппонент слишком силён), играть не с ним, а с его историческими чекпоинтами по `f_var` (автоматический curriculum);
- "verification branch" (15%): если min win-rate против исторических exploiters < 0.3 - играть против них; если min win-rate против исторических чекпоинтов оппонента < 0.7 - тоже (проверка forgetting);
- чекпоинт main не раньше 2e9 шагов и при min win-rate против всех исторических > 0.7 либо > 4e9.

**Масштаб**: 12 параллельных копий actor-learner (по 1 MA, 1 ME, 2 LE на три расы), каждая на 32 TPUv3, 44 дня, ~900 различных игроков в лиге; coordinator хранит оценку payoff-матрицы, CPU-evaluator-воркеры "supplement the payoff estimates" (прямой прототип нашего Coordinator + WinRateTracker).

**Абляции (Fig. 3, упрощённая постановка: одна карта, Protoss vs Protoss, 1e10 шагов)**:

| Вариант | Test Elo | Примечание |
|---|---|---|
| только main agents | 1540 | RPP 6% |
| + main exploiters | 1693 | RPP 35% |
| + league exploiters | 1824 | RPP 62% |
| pFSP+SP | 1540 | min win-rate vs прошлые 71% |
| чистый SP | 1519 | min win-rate vs прошлые 46% (сильное забывание) |
| pFSP | 1273 | медленнее |
| FSP | 1143 | медленнее |

Нетранзитивность в AlphaStar сосредоточена в exploiters: ~3 000 000 RPS-циклов (при порогах win-rate 70%) с участием хотя бы одного exploiter против ~200 среди одних main (Extended Data Fig. 8) [V]. Main agents ведут себя в основном транзитивно.

### 1.2. Упрощённые лиги

- **TStarBot-X** (Tencent, arXiv 2011.13729) [V]: 144 V100 (96 обучение + 48 inference), 13 440 CPU-ядер, 57 дней, модель 20M параметров (AlphaStar 139M), ~1/30 ресурсов AlphaStar. "AlphaStar Surrogate" (1 MA + 2 ME + 2 LE) сходился в ранние rush-стратегии. Что помогло: новые роли exploiters - Specific Exploiter (старт от fine-tuned supervised под конкретную стратегию), Evolutionary Exploiter и **Adaptive Evolutionary Exploiter (AEE)**: наследуется не от supervised, а от "листового" исторического узла, чей win-rate против MA в интервале 20-50%, то есть не теряет прогресс. MA: 25% SP, 60% PFSP, 15% PFSP против forgotten; снапшот каждые 3e8 шагов (~12 часов). Итоговая лига: 1 MA + 8 exploiters, 583 агента за 57 дней. **DAPO**: `KL(pi_{t-1} || pi_t)` к предыдущей версии себя (период ~12 часов), включён в последние 15 из 57 дней, заметно ускорил рост. **RGPS**: `KL(pi_rule || pi_theta)` на небольшом множестве "критических" состояний (перенос идеи "скриптовые правила -> KL-регуляризация").
- **ROA-Star** (Tencent, NeurIPS 2023) [V]: 64 V100 и 4600 CPU-ядер на агента, 50 дней, 768 моделей; снапшот MA каждые 2e8 шагов, ME сбрасывается максимум через 4e8, LE через 2e8. Идея: exploiters, условные на цель z, плюс opponent modeling, потому что в реимплементации AlphaStar exploiters со временем теряют способность находить слабости.
- **SCC (StarCraft Commander, ICML 2021)** [V]: лига AlphaStar-стиля, но с несколькими main агентами и **agent branching**: новый агент инициализируется от текущего main, а не от supervised. Позднее стартовавший main догнал первый по Elo примерно за 15 дней. Масштаб на агента ~1000 параллельных сред (AlphaStar 16 000). Системная часть: общий кластер Predictors (inference для всех агентов лиги), MySQL для данных лиги, Scheduler и Evaluator.
- **TLeague** (arXiv 2011.12895) [V]: фреймворк CSP-MARL: Actor, Learner, InfServer, ModelPool, LeagueMgr, GameMgr (payoff + выбор оппонента), HyperMgr (PBT). Для K>=2 оппонентов: оппонент выбирается **независимо для каждого слота** в начале эпизода. Pommerman 2v2 с нуля: смесь 35% SP + 65% PFSP.
- **AlphaStar Unplugged** (arXiv 2308.03526) [V]: лиги нет, но полезный протокол оценки: **фиксированный набор из 7 оппонентов** (very_hard bot + 6 референсных агентов); Elo с якорем (very_hard = 1000), рейтинг нового агента подгоняется без изменения референсов; метрика robustness = 1 - min_q win-rate(p, q) (1 - exploitability относительно референсного набора).
- **Honor of Kings** (arXiv 2011.12692) [V]: лиги нет. Curriculum self-play: фаза 1 - self-play на фиксированных составах, фаза 2 - multi-teacher distillation в одну модель, фаза 3 - случайные составы. Ресурсы: 320 GPU + 35 000 CPU. Для нас: идея "обучить узких teacher-ов, затем дистиллировать", если у игры много конфигураций.
- **OpenAI Five** (arXiv 1912.06680) [V]: 80% игр против latest, 20% против прошлых. Прошлые выбираются по quality score: `p_i ∝ exp(q_i)`; каждые 10 итераций текущий агент добавляется в пул с `q = max(q)`; после игры, если текущий победил i-го: `q_i <- q_i - eta / (N * p_i)`, `eta = 0.01`; при проигрыше текущего обновления нет. Эффект: быстро растущий агент перестаёт играть против слабых старых. Scripted-оппонентов в пуле нет; был ruler-пул из 83 референсов с замороженным TrueSkill (раздел 3).
- **FTW (Quake III CTF)** (arXiv 1807.01281) [V]: популяция из 30 агентов (PBT), матчи 2v2; matchmaking: первый агент uniform, остальные без возвращения из `N(P(win) - 0.5; sigma)` (центрировано на равном уровне; значение sigma в тексте искажено, вероятно 1/6 [не подтверждено]). PBT: если win-rate < 70%, проигравший копирует политику, внутренний reward и гиперпараметры победителя и мутирует (+-20% с вероятностью 5%). Командный Elo - аддитивная модель.
- **Hide & Seek** (arXiv 1909.07528) [V]: чистый self-play без пула; для эмерджентных, в основном транзитивных сред достаточно. Большие batch сильно ускоряют по wall-clock.
- **Bansal et al. 2018** (arXiv 1710.03748) [V]: оппонент ~ Uniform(delta * v, v), v - последняя итерация. delta=1: только latest; delta=0: вся история. Результат: Humanoid - delta=0.5 лучше, Ant - delta=0 лучше, то есть **0.5 не универсальная константа**. Ансамбль из нескольких одновременно обучаемых политик (пул из 3, каждая играет против случайной другой) борется с переобучением на одного оппонента - обоснование arena-режима. Dense exploration reward линейно затухает за 500 итераций.

### 1.3. PSRO и практичные варианты

- **PSRO** (Lanctot 2017) [V]: oracle (approx. best response) обучается против mixture популяции по meta-solver (Nash, uniform, regret matching и т.д.); обобщает независимый RL (mixture = latest) и fictitious play (uniform). Независимый RL переобучается на со-игроков (joint-policy correlation).
- **Pipeline PSRO** (McAleer 2020) [V]: иерархия worker-ов, "active" обучаются параллельно, нижняя фиксируется при плато и добавляется новая. Можно взять **идею фиксации снапшота по плато роста вместо таймера**.
- **NeuPL / Simplex-NeuPL / NeuPL-JPSRO** [V]: вся популяция - одна условная сеть `pi(a | s, sigma_i)`; популяция размера 8 уже достаточна. Требует conditional-политику и переписывания интерфейса.
- **XLand** [V]: поколения; лучший агент поколения становится teacher (distillation) и со-игроком.
- **Fictitious Cross-Play** (2023) [V по аннотации]: в смешанных кооперативно-соревновательных играх self-play не гарантирует сходимость к NE.
- **Delta-uniform / FSP / historical averaging**: FSP в deep RL = Monte-Carlo сэмплирование оппонента из пула в начале эпизода (TLeague); delta-uniform = Bansal. "Mixed-Opponent" как отдельный именованный метод не найден [не подтверждено].

### 1.4. Что реально стоит усилий для команды 1-3 человека за 2-8 недель [рекомендация, опирается на абляции выше]

Масштаб для сравнения: AlphaStar ~3072 TPU-ядра x 44 дня; TStarBot-X 144 GPU x 57 дней; Colosseum на 1-8 машинах - на 3-4 порядка меньше.

| Уровень | Что | Цена | Эффект (источник) |
|---|---|---|---|
| L0 | FIFO/растущий пул + latest 70-85% | уже есть | базовая защита от strategy collapse (OpenAI Five, Bansal) |
| L1 | Смесь 35% SP / 50% PFSP по пулу / 15% verification; PFSP `squared`; win-rate с затуханием; пул чекпоинтов не FIFO, а прореженный (последние N + логарифмическая сетка старых) | 2-4 дня | SP+PFSP: min win-rate vs прошлые 71% против 46%, Elo 1540 против 1143-1273 у чистого PFSP/FSP |
| L2 | **Gauntlet** (фиксированные референсы: scripted + 3-10 замороженных чекпоинтов из разных фаз) для абсолютной шкалы | 1-2 дня | Unplugged: robustness = 1 - min win-rate; защита от дрейфа и гонки "зеркал" |
| L3 | 1 main exploiter на main агента (старт с BC/лучшего чекпоинта, играет только против текущего main; снапшот при >70% либо таймаут ~2x интервала снапшота main) | ~1 неделя | +153 Elo, RPP 6% -> 35% в абляции |
| L4 | League exploiter + AEE-наследование вместо сброса | по остаточному бюджету | +131 Elo, RPP 35% -> 62%; платит числом параллельных learner-процессов |
| не делать | NeuPL, P2SRO/DCH, alpha-PSRO, PBT гиперпараметров, 12 параллельных линий | - | требуют нового интерфейса политики или недоступных ресурсов |

Практическое правило интервала снапшота: AlphaStar MA 2e9 из ~1.9e11 шагов (~1%), ROA-Star 2e8 из 4.42e10 (~0.45%) [расчёт]; ориентир для нас - 0.5-2% полного бюджета шагов на снапшот. TStarBot-X подтверждает: **не масштабировать таймеры AlphaStar вниз буквально**.

Arena-режим (несколько trainable агентов одновременно, как FTW/Bansal) в Colosseum оставить; matchmaking внутри арены лучше делать по близости Elo/win-rate (FTW: нормальное распределение вокруг равной силы), чтобы не терять учебный сигнал.

## 2. N-игроковые FFA и командные игры

### 2.1. Формирование матчей [V по источникам, рекомендации отмечены]

- TLeague для N>=2: оппонент выбирается независимо для каждого слота `phi ~ Q(M)` в начале эпизода.
- FTW (2v2): первый агент uniform, остальные по нормальному распределению вокруг P(win) = 0.5; команды случайные.
- Bansal: ансамбль политик, для каждого rollout выбирается случайная другая; для симметричных игр оппонент может быть той же политикой.
- OpenAI Five: обе команды управляются копиями одной политики (80/20).
- Pluribus: 1 ИИ против 5 людей и 1 человек против 5 копий ИИ; порядок мест случайный в начале каждого дня. Self-play на практике работает в 6-max покере без гарантий вне 2p0s.
- Diplomacy: оценка в формате "1 агент типа A против 6 агентов типа B" (Gray et al.), средний счёт идентичного агента 1/7 = 14.3%.

**Рекомендация для Colosseum (N слотов)** [рекомендация]:
- `solo` (1 learner-слот): остальные N-1 слотов - независимые сэмплы из пула (как TLeague); дополнительный формат "1 vs (N-1) копий одного оппонента" для чистой оценки эксплуатации конкретного оппонента;
- `self` (все слоты = latest): дешёвый self-play с N-кратным сигналом (нужно seat-agnostic наблюдение или seat embedding);
- `arena`: K trainable агентов с произвольным числом слотов на агента (не только 2), остальные слоты - frozen/scripted по PFSP;
- число learner-слотов можно семплировать (например, Binomial), а не фиксировать.

### 2.2. Награды [V по источникам]

- **Hungry Geese, победитель HandyRL** (код `handyrl/envs/kaggle/hungry_geese.py`): ранг переводится в попарные сравнения, `outcome_p = sum_{q != p} sign(r_p - r_q) / (N-1)`; для N=4: +1, +0.33, -0.33, -1; zero-sum, одинаковая цена перехода на одно место, сразу даёт попарные исходы для PFSP/рейтингов.
- OpenAI Five: shaped reward + **team spirit** `r_i = (1 - tau) * rho_i + tau * mean(rho)`; tau: 0.3 -> 0.8 (Rerun, план -> 1.0); затухание каждой награды по времени игры `rho <- rho * 0.6^(T/10 мин)`; zero-sum (вычитание среднего награды противников).
- Zero-sum shaping критичен в self-play: WeKick ("making it zero-sum is very important"), EcoBangBang (переход на zero-sum baseline сыграл ключевую роль), Frog Parade.
- Lux S1 (Toad Brigade): shaping только первые 20M шагов, затем sparse +-1; Hide&Seek: командный zero-sum +-1.
- Diplomacy: sum-of-squares scoring `C_i^2 / sum_j C_j^2` - пример non-zero-sum награды.

[рекомендация] `BaseEnv` возвращает финальные места (с ничьими), а фреймворк сам строит reward по схеме `pairwise_mean` (формула HandyRL) или `linear_placement`; плюс опциональный dense shaping с расписанием затухания и `team_spirit`.

### 2.3. Результат против конкретного оппонента в FFA [V по источникам]

1. **Попарное извлечение из рангов**: для каждой пары слотов (i, j) исход 1 / 0.5 / 0 по сравнению мест. Gray et al. (Diplomacy): рейтинг подгоняется по `L(s) = sum_{(i,j)} -log sigma(s_i - s_j) + lambda * |s|^2`, "более правдоподобные оценки, чем Elo и TrueSkill". Пары внутри одной игры коррелированы, поэтому **bootstrap по матчам, а не по парам** [рекомендация].
2. **Plackett-Luce по полному рангу**: `P(sigma | s) = prod_k exp(s_{sigma(k)}) / sum_{l>=k} exp(s_{sigma(l)})`; реализации: OpenSkill `PlackettLuce` (онлайн), `choix.ilsr_rankings` (batch MLE).
3. **Обобщённый BayesElo** (Diplodocus): ожидаемая доля счёта `∝ exp((r_i + b_{s(i)})/c)`, `b_s` - преимущество места (seat), MAP-подгонка со слабым prior N(0, ~350 Elo).
4. **Командный аддитивный Elo** (FTW): `P(blue) = 1 / (1 + 10^(-psi^T m / 400))`, `m_i` = (число появлений агента i в blue) - (в red); работает при транзитивных составах.
5. **Для PFSP**: хранить win-rate по парам (агент A, агент B), обновляя (i, j)-парами из каждого матча с весом `1 / (число пар, содержащих A)`, чтобы большие N не раздували вес матча [рекомендация].
6. Обобщённая exploitability для N игроков (Gray): `e(pi) = (1/N) * sum_i [max_{pi*_i} v_i(pi*_i, pi_{-i}) - v_i(pi)]`; практически - best-response через обученный exploiter.

### 2.4. Seat / position bias [V по источникам]

- Pluribus: случайный порядок игроков; FTW: случайная раскладка по командам и повороты карты; Diplodocus: seat/power bias встроен в рейтинговую модель; Gray: счёт при равных весах держав 26.9% +- 3.3%.
- [рекомендация]: **обучение** - случайная перестановка мест в каждом эпизоде (маппинг слот -> агент перемешивается независимо от индекса среды), наблюдение эго-центричное; **eval** - полная ротация (для M агентов Latin-square / сбалансированные блоки, чтобы каждый агент занимал каждое место поровну); при асимметрии мест - параметр `b_seat` в модели рейтинга и логирование win-rate по местам как диагностика. В chess-движках аналогичный приём - пары игр с обменом цветов и pentanomial-модель (раздел 3.3).

### 2.5. Self-play при N>2, нетранзитивность

- Pluribus: self-play (MCCFR) успешен в 6-max покере: 48 mbb/game (stderr 25) в 5H+1AI и 32 mbb/game (stderr 15) в 1H+5AI; 12 400 CPU-core hours.
- Diplomacy (7 игроков, смешанные мотивы): self-play с нуля (DORA) даёт агентов, которые сильны против копий себя, но **независимые запуски сходятся в несовместимые равновесия и проигрывают друг другу**. Решения: KL-регуляризация к human-imitation policy (DiL-piKL / Diplodocus: 200 игр, 62 человека, 1-е и 3-е места по Elo), поиск.
- [рекомендация]: держать минимум 2-3 независимых lineage/архитектур и мерить cross-play матрицу; расхождение значительно ниже/выше 50% между независимыми seed-ами - признак нетранзитивных конвенций. Для командных игр: опциональный centralized critic и `team_spirit`; QMIX/MADDPG отложить.
- Не делать как основной рейтинг: alpha-Rank/CCE-рейтинг при N>2 (число профилей растёт как n^N), NeuPL, PSRO с LP-Nash в N-игроках (Nash не уникален).

### 3.2. Рейтинги исторических чекпоинтов

- **OpenAI Five** (прямой прецедент) [V]: ruler-пул из **83 референсов с замороженным TrueSkill** (0..254), параметры `sigma=25/3, beta=sigma/2, tau=0.0, draw_probability=0.02`; тестируемый агент играет только с референсами **в пределах 10 пунктов TrueSkill**; после игры обновляется только рейтинг тестируемого (референс - константа); версия логируется после 750 игр; **новый агент наследует mu предыдущей версии**. Числа "разность 8.3 TrueSkill = 80% побед" из статьи расходятся с формулой при beta=sigma/2 (получается ~92%) - не копировать без проверки [не подтверждено].
- **Наследование как prior** [рекомендация]: `mu_init = mu_parent`, `sigma_init >= sigma_parent`; для BT-MLE - L2-регуляризация не к нулю, а к рейтингу родителя (новый чекпоинт без игр получает рейтинг родителя, данные постепенно доминируют). Прямого прецедента для BT в источниках не найдено [не подтверждено].
- **Дрейф онлайн-Elo в цепочке чекпоинтов [SIM]** (100 чекпоинтов, каждый на +10 Elo сильнее, истинный диапазон 990 Elo, 40 игр на новый чекпоинт, 5 сидов):

| Схема | окно оппонентов | RMSE, Elo | оценка диапазона |
|---|---|---|---|
| online Elo K=32 | все | 72.9 | 960 |
| online Elo K=32 | последние 10 | 135.9 | 821 |
| frozen-оппоненты K=32 | все | 72.5 | 929 |
| frozen K=32 | последние 10 | 91.6 | 923 |
| batch BT-MLE | все | 71.8 | 955 |
| batch BT-MLE | последние 10 | 82.0 | 926 |

Вывод: при локальном матчинге онлайн-Elo сжимает шкалу; нужны "дальние" связи (случайные игры с далёкими чекпоинтами, что даёт PFSP-смесь), batch BT или замороженные оппоненты. Ограничения симуляции: одна конфигурация, 5 сидов.
- **Нетранзитивность**: Elo/BT на RPS даёт равные рейтинги и предсказание 50%. Диагностика [рекомендация + V Balduzzi]: антисимметричная матрица логитов `A_ij = logit(P_ij)`, Elo-часть = row-mean, остаток = циклическая часть (Hodge); доля нормы остатка - индикатор. Порог ~20-30% - моя эвристика. Elo "накручивается" клонами слабого агента [SIM: 95 -> 300 при 10 клонах, Nash average остался 0].
- **AlphaStar метрики лиги**: Elo с якорем (Elite bot = 0), RPP `Nash(P_AB)_A^T P_AB Nash(P_AB)_B`, min win-rate против прошлых версий (forgetting), доля validation-агентов, побеждающих main (>80 из 160 игр).

### 3.3. Как надёжно выбрать лучший чекпоинт для сабмита

**Доверительные интервалы и объёмы выборки [SIM]**. Wilson 95%, p=0.5:

| n игр | 50 | 100 | 200 | 400 | 1000 | 2000 | 5000 | 10000 |
|---|---|---|---|---|---|---|---|---|
| полуширина, Elo | 95.1 | 67.7 | 48.0 | 34.0 | 21.5 | 15.2 | 9.6 | 6.8 |

Игр для обнаружения ΔElo (односторонний alpha=0.05, мощность 80%, без ничьих): 5 Elo -> 29 856; 10 -> 7467; 20 -> 1870; 30 -> 833; 50 -> 303; 100 -> 79; 200 -> 23 (при доле ничьих 0.3 умножить примерно на 0.7, при 0.6 - примерно на 0.4). Для N>2 брать эмпирическую дисперсию score/placement и пересчитывать `n ∝ sigma^2 / Delta^2`. Соответствия: 55% = +34.9 Elo, 60% = +70.4, 75% = +191.

**SPRT (fishtest/Stockfish)** [V: van den Bergh; fishtest wiki]:
- Границы остановки `[ln(beta/(1-alpha)), ln((1-beta)/alpha)]`: alpha=beta=0.05 -> +-2.944; (0.01, 0.05) -> [-2.986, 4.554]; (0.05, 0.2) -> [-1.558, 2.773].
- Точный LLR для бинарных исходов: `LLR = W ln(p1/p0) + L ln((1-p1)/(1-p0))`, `p_i = 1/(1+10^(-elo_i/400))`.
- GSPRT-приближение: `LLR ≈ (1/2)(phi1 - phi0)(2 phi_hat - phi0 - phi1) / V(phi_hat)`, `V` из мультиномиальной модели; **pentanomial** (пары игр с обменом цветов/мест, 5 исходов пары) даёт заметную экономию игр, потому что учитывает корреляцию внутри пары.
- Normalized Elo: `t_n = (mu - 1/2)/sigma_pg`, `e_n = C t_n`, `C = 800/ln10 ≈ 347.43`; `e_n` не зависит от доли ничьих. Ожидаемая длительность `T ≈ 10^6 / Delta^2` игр (Delta - разность normalized Elo H1-H0): Delta=1 -> 1 046 535; 3 -> 116 282; 6 -> 29 070.
- [SIM] проверка бинарной формулы: ошибки I/II рода в пределах ожидаемых ~5%; при истине посередине между H0 и H1 тест длиннее всего (~1.6x).
- Типичные границы (CPW): Stockfish LTC gainer [0.5, 2.5], non-regression [-1.75, 0.25]; единицы Elo (BayesElo/logistic/normalized) в разные эпохи различались [не подтверждено, в каких именно строках].
- Применение в Colosseum [рекомендация]: **gating публикации/сабмита** ("кандидат не хуже/лучше текущего champion на elo1 минимум 10-20 Elo"), при K кандидатах поправка Bonferroni (alpha/K); для N>2 свести матч к "доле очков кандидата против поля" и применять GSPRT по эмпирической дисперсии.

**Winner's curse [SIM, 2000 повторов]**:

| K кандидатов | игр на каждого | разброс истинных сил (sd, Elo) | завышение выбранного, Elo | P(выбран истинно лучший) |
|---|---|---|---|---|
| 5 | 400 | 0 | 20.2 | 0.20 |
| 5 | 1600 | 20 | 4.1 | 0.75 |
| 20 | 400 | 0 | 32.1 | 0.04 |
| 20 | 400 | 20 | 21.4 | 0.41 |
| 20 | 1600 | 20 | 6.9 | 0.61 |
| 100 | 400 | 20 | 29.0 | 0.28 |
| 100 | 1600 | 50 | 4.0 | 0.76 |

Типичные соседние чекпоинты различаются на 5-20 Elo, а 400 игр дают +-34 Elo: выбор "лучшего из 20" практически лотерея. Аналог в публичных рейтингах: "The Leaderboard Illusion" (Meta протестировала 27 приватных вариантов Llama-4 и опубликовала лучший) [V по аннотации].

**Лечение (протокол выбора)** [рекомендация]:
1. Фиксированный benchmark/gauntlet (scripted + замороженные чекпоинты разных фаз + пойманные exploiters); метрики: win-rate с CI, **min win-rate по оппонентам** (max-min), Nash-value против пула.
2. Successive halving (Jamieson-Talwalkar): раунд 1 - по m игр всем K чекпоинтам, отбросить нижнюю половину, удвоить m; экономия ~4-10x игр.
3. Финалист(ы) **перемеряются на независимых играх** (новые сиды, новые слоты, новые оппоненты) - несмещённая оценка победителя.
4. Симультанные CI: Bonferroni или chi-квадрат-множество как в Arena; чекпоинты, чьи интервалы пересекаются с лучшим, считать неразличимыми и выбирать среди них по другому критерию (min exploitability, "последний на плато", усреднение весов).
5. Сглаживание: выбирать по кривой рейтинга по шагам обучения (скользящее среднее), а не по argmax точек.
6. "Последний vs лучший": AlphaZero отказался от best-selection и всегда играет последней сетью; правило: брать последний чекпоинт плато, если CI разности с argmax включает 0.
7. **Усреднение весов**: EMA/SWA (KataGo: кандидат = EMA 4 последних снапшотов, decay 0.75, gating >=100 из 200); greedy model soup из последних K чекпоинтов с проверкой на hold-out; для LSTM/GRU и разных seed может ломаться - проверять матчем [не подтверждено для self-play RL с LSTM].

### 3.4. Gating кандидатов в лигу/пул [V по статьям, [SIM] по статистике порогов]

| Система | Правило |

| OpenAI Five | gating нет; пул растёт, softmax по quality |
| AlphaStar | расписание снапшотов для main (без порога), порог 70% против всех для exploiters |

Статистика порогов [SIM]: правило 55%/400 игр (>=220) пропускает кандидата с +10 Elo лишь в 8% случаев, +35 Elo - в 52%, +70 - в 98%; правило KataGo 100/200 пропускает кандидата с 0 Elo в 53% случаев, с -10 Elo - в 37% (защита только от явной деградации). Вывод: жёсткий gating блокирует медленный прогресс RL (+5-10 Elo за шаг); для **тренировочного пула** gating не нужен (AlphaStar снапшотит по расписанию), для **публикации/сабмита** нужен мягкий SPRT-gating с Bonferroni.

## 4. Скриптовые боты в популяции

### 4.1. Зачем (роли)

| Роль | Суть | Подтверждение |
|---|---|---|
| Anchor / ruler | Self-play Elo относителен и дрейфует; нужны неизменные референсы | OpenAI Five (83 референса), FTW (scripted Quake-боты в Elo-турнире), AlphaStar (Elite bot = 0), Unplugged (7 референсов) |
| Curriculum / bootstrap | Против слабого предсказуемого бота у свежей политики ненулевой win-rate | Bansal 2018, Toad Brigade (rules-агент как отправная точка) |
| Защита от forgetting | Фиксированные стратегии в пуле не "забываются" и штрафуют регресс | AlphaStar verification branch |
| Защита от overfitting к self-play / co-players | Независимый RL переобучается на со-игроков (JPC) | Lanctot 2017, Gleave 2020, Wang 2023 |
| Teacher | Скрипт как источник меток для kickstarting/RGPS | TStarBot-X RGPS, JSRL guide |
| Sparring partner | Узкий известный набор стратегий; **не заменяет лигу**: нетранзитивные циклы лежат вне набора | Czarnecki 2020 |

Скриптовых ботов в тренировочном пуле AlphaStar и OpenAI Five нет (скрипты - только оценка); использование в обучении - практика Kaggle-команд и инженерное решение владельца [вывод].

### 4.2. Пропорции

Прямых исследований оптимальной доли скриптовых оппонентов не найдено [не подтверждено]. Опорные ориентиры для истории: OpenAI Five 20% past; AlphaStar main 50/35/15; Bansal delta в [0, 0.5]; Boey 25% frozen past + PFSP; Kiwis 25% против последних 128 чекпоинтов.

Рекомендация [эвристика, требует sweep]: anchors - фиксированные не-обучаемые слоты (`collect_trajectories=False`, не выходят из пула); **10-20% матчей** содержат хотя бы один anchor-слот, доля **не затухает** до нуля (иначе теряется функция защиты от забывания); внутри anchors PFSP `squared` с **нижней границей вероятности 2-5% на каждого** (пройденный бот не должен исчезать); в ранней фазе после BC доля scripted выше (30-50%) с линейным спадом к 10-20%.

### 4.3. Curriculum оппонентов

Подтверждённые механизмы [V]: self-play как автоматический curriculum (Bansal, Hide&Seek); автооткат на слабых при слишком сильном оппоненте (AlphaStar: `winrate <= 0.3` -> исторические чекпоинты оппонента по f_var); dense exploration reward -> sparse (Bansal: линейно за 500 итераций; Toad Brigade: 20M шагов); постепенное включение нового (OpenAI Five: 0% -> 100% игр с новой механикой, откат при просадке TrueSkill); цепочка размеров сети (Toad Brigade: 8 -> 16 -> 24 блока с предыдущей сетью как teacher); JSRL (guide ведёт первые h шагов, h убывает).

Предлагаемый порядок [вывод]: scripted (слабые) -> scripted + замороженные BC/ранние чекпоинты -> self-play (latest + пул) -> PFSP league (+ exploiters + anchors). Переход по gate-метрике (win-rate против anchor > порога, по аналогии с AlphaStar `0.7`), а не по числу шагов.

### 4.4. Exploitability и exploiters [V]

- **Gleave 2020** (arXiv 1905.10615): adversary, обученный против замороженной victim, выигрывает, затратив <3% timesteps обучения victim, за счёт off-distribution наблюдений. Fine-tune victim только против adversary вызывает catastrophic forgetting; "dual" (adversary или обычный оппонент) лучше, но хуже оригинала; новый adversary находится снова.
- **Wang 2023** (arXiv 2211.00241): adversary против KataGo: >99% без поиска и >97% при "superhuman" поиске, <14% compute обучения KataGo; hard-coded защита закрыла один эксплойт, но циклический выигрывает 95.7% против защищённой версии.
- **Tseng 2024** (arXiv 2406.12843): три защиты (positional adversarial training, iterated adversarial training, ViT) провалились против свежих adversaries (атака за 8-26% compute защиты). Вывод: нужны **постоянные** exploiters и diversity, а не разовая проверка.
- Практический протокол `colosseum eval --exploit` [вывод]: заморозить A; обучить exploiter на 3-10% бюджета A; метрики - win-rate exploiter vs A с Wilson CI и win-rate A против anchors (чтобы A не деградировал в среднем); exploiter-чекпоинт добавить в пул как frozen (A обязан учиться против него, как main exploiters у AlphaStar); периодически повторять; для N-игроков exploiter занимает 1 слот.

### 4.5. Catastrophic forgetting: причины и лекарства [V]

Причины: оптимизация против текущего оппонента ("strategy collapse", OpenAI Five), нетранзитивные циклы, переобучение на со-игроков. Лекарства: прошлые чекпоинты (Bansal delta, 20% OpenAI Five), FSP/PFSP (в AlphaStar PFSP лучше FSP по population performance и exploitability), **verification branch** (целенаправленная проверка min win-rate < 0.7), exploiters, KL к frozen teacher (Toad Brigade: "prevent strategic cycles - problems that plague a pure self-play setup"; DAPO к предыдущей версии), dual/mixed fine-tuning при патче эксплойта, Elo относительно якоря для видимости регресса.

### 4.6. OpenAI Five: surgery и Rerun [V]

>20 surgery за 10 месяцев, Rerun: 150 PFlops/s-days (~20% ресурсов), ~2 месяца, >98% побед против финального Five; без surgery проект занял бы ~40 месяцев вместо 10 (оценка авторов). Критично: все замороженные прошлые агенты нужно преобразовывать тем же surgery, иначе они "навсегда играют хуже" и портят пул. Для Colosseum [вывод]: хранить в каждом чекпоинте собственный `NetworkConfig` и версию encoder-а; worker network pool уже работает по `(agent_id, network_id)`, поэтому старые чекпоинты можно **не конвертировать**, а загружать со старой архитектурой.

## 5. Варианты warm start и переходы между фазами

Общая оговорка [V, DE_notes]: коэффициенты потерь нельзя переносить между кодовыми базами напрямую (зависят от нормировки advantage, суммирования по action heads, масштаба value loss); все числа ниже - точки отсчёта для sweep.

### 5.1. Offline BC на больших датасетах реплеев

- **AlphaStar supervised** [V по `supervised.py`]: batch 512, trajectory 64, Adam lr 1e-3, loss = cross-entropy + 1e-5 L2, 128-core TPUv3; LSTM-состояние переносится между соседними траекториями; `FINE_TUNING`: порог MMR 6200, lr 1e-5; основной срез MMR > 3500; число реплеев ~971 000 [S, только вторично]; результат: supervised 3699 MMR (лучше 84% людей). Условие на стратегию z и MMR игрока подаются на вход; при RL ставят высокий MMR.
- **AlphaStar Unplugged** [V]: ~20M игр -> ~5M после фильтра версий -> ~1.4M игр с MMR>3500 (2.8M эпизодов); BC cosine lr0 = 5e-4, FT-BC lr0 = 1e-5 на top-tier; return-conditioned BC, Q-learning и off-policy оценка не превзошли unconditional BC; работает one-step offline RL (оценить behavior policy и behavior value, затем улучшить).
- **Kaggle-датасеты**: Meta Kaggle (таблицы Episodes/EpisodeAgents [S]), скрейперы эпизодов (`kaggle competitions episodes/replay/logs` в kaggle-api [V по исходникам]); Lux S2 организаторы дали >1 млрд кадров play-данных. Практика фильтрации: **только эпизоды, где все участники выше порога рейтинга**, порог растёт по ходу соревнования (Goosebumps, ironbar); условный вход "кого имитировать" (ironbar: Conditioned UNet 24M, <1 суток на 3090; Durrett: shared CNN + отдельный head на донора).
- **Pitfalls** [V]: compounding error `J(pi) <= J(pi*) + T^2 * eps` (Ross), мультимодальность эксперта (cross-entropy, а не MSE-среднее), данные разной силы (фильтр/conditioning), LSTM нужны длинные последовательности с переносом hidden.
- **DAgger** [V]: `pi_i = beta_i pi* + (1-beta_i) pi_hat_i`, обучение на агрегате всех собранных данных; `beta_1 = 1`, простая версия `beta_i = I(i=1)` "often performs best". Применимо только если эксперт доступен в рантайме (скрипт).
- **GAIL / AIRL / IQL** [V]: GAIL требует on-policy RL внутри (используется WeKick для разнообразия оппонентов); AIRL восстанавливает reward (reward ambiguity = potential shaping); IQL - expectile regression для offline critic. Для реплеев без reward проще BC + KL.
- Потолок IL = качество донора: ironbar (5-е место Lux S1) сам признаёт, что IL копирует лидера, но не превосходит (Toad Brigade был на ~300 LB-очков выше).

### 5.2. Kickstarting, distillation, KL-регуляризация [V]

- **Policy distillation** (Rusu 2015): для Q-teacher лучшая функция - KL с низкой температурой (tau=0.01); для policy-teacher softmax не нужен.
- **Kickstarting** (Schmitt 2018, arXiv 1803.03835): `l_kick = l_RL + lambda_k * H(pi_T || pi_S)` (cross-entropy teacher -> student, то есть forward KL плюс константа), траектории генерирует студент, `lambda_k = 0` после `T_0`. Расписания (DMLab-30, IMPALA, 10B кадров): constant 1-2 плато около teacher ("trying too hard to match"); **linear 1 -> 0 за 1-4B кадров лучше**, "important to reduce this weight quickly"; PBT-управление lambda почти так же хорошо, как лучшее ручное расписание. Эффект с одним малым teacher: 37.4 против 24.1 на 0.5B кадров; 56.9 против 51.9 на 10B. Multi-teacher: `lambda^i = alpha * rho^i`.
- **AlphaStar RL** [V по `rl.py`, `detailed-architecture.txt`]: `kl = teacher_probs * (t_logprobs - s_logprobs) * mask` по **каждому** аргументу действия с маской допустимых; distillation weight 2e-3 на все аргументы, entropy 1e-4, для условных на z траекторий дополнительно 1e-1 на action_type logits; KL **не отжигается** в описанных константах ("ensures a wide variety of relevant modes of play continue to be explored"); RL = V-trace + UPGO (вес 1.0) + TD(lambda=0.8) baseline (вес 10.0). Расхождение "первые 4 минуты" в тексте и `game_seconds > 4*60` в коде [не подтверждено].
- **VPT** (Baker 2022, arXiv 2206.11795) [V, Table 6]: PPG, lr 2e-5, weight decay 0.04, gamma 0.999, GAE lambda 0.95, PPO clip 0.2, max grad norm 5, max staleness 2; **KL-коэффициент rho = 0.2, decay 0.9995 за итерацию** (half-life ~1386 итераций, через ~4600 итераций rho ~0.02 [расчёт]); "KL REPLACES entropy bonus"; **value head инициализирован нулями** ("prevent destructive updates early"), value targets нормализованы EMA mean/std; без KL lr пришлось снизить с 2e-5 до 3e-6; без KL агент теряет поздние навыки (catastrophic forgetting), RL с нуля - почти 0 reward.
- **QDagger / Reincarnating RL** (Agarwal 2022, arXiv 2206.01626) [V]: `L = L_TD + lambda_t * E[sum_a pi_T(a|s) log pi(a|s)]`; lambda убывает линейно по шагам или как функция отношения производительности студента к teacher; student обучается 10M кадров (в 40 раз меньше teacher), "wean off at 6M"; kickstarting и DQfD деградируют при weaning, QDagger нет; превышает teacher в 75% запусков.
- **TStarBot-X DAPO / RGPS** [V]: см. раздел 1.2.

**Направление KL** (критично, G1): Kickstarting, AlphaStar, VPT, QDagger - все teacher-first. Причина [вывод]: forward KL заставляет студента покрыть все моды teacher (сохраняет разнообразие и exploration); reverse KL mode-seeking допускает схлопывание. Рекомендация: в `kickstart.py` параметр `kl_direction: forward | reverse`, по умолчанию `forward`; обновить CLAUDE.md и `kickstart_*` описание в `TrainingConfig`. В APPO teacher logits можно (а) пересчитывать на learner (проще, поддерживает несколько teacher/версий) или (б) считать на worker и хранить в chunk (как поле `teacher_logits` в AlphaStar, экономит GPU learner).

### 5.3. Другие мосты BC -> RL

- **JSRL** (Uchendu 2022, arXiv 2204.02372) [V]: guide-policy ведёт первые h шагов эпизода, затем обучаемая политика; h убывает по curriculum, когда score комбинации достигает порога beta. Не нужен KL. Важное наблюдение (Fig. 2): pretrained actor + **случайный critic** -> производительность падает, "the untrained critic provides a poor learning signal, causing the good initial policy to be forgotten"; baseline "critic warm-up" - 100k шагов rollout-а pretrained policy при замороженном actor.
- **PORL** (2025) [S, abstract/intro]: предобученные консервативные Q мешают exploration; инициализировать Q с нуля онлайн.

### 5.4. Reward shaping и аннилинг [V]

- Potential-based (Ng, Harada, Russell 1999): `F = gamma Phi(s') - Phi(s)`, сохраняет оптимальную политику (необходимо и достаточно); точная формулировка теоремы получена только вторично, через AIRL [S]. Шейпинг вне этого класса меняет оптимум (OpenAI Five: "guarantees do not apply").
- Аннилинг `r' = r_sparse + sum_k w_k(t) r_k`, `w_k` -> 0 линейно или экспоненциально по числу learner steps: Toad Brigade (shaping 20M шагов, затем sparse), FLG (~65M шагов selfish dense, затем zero-sum; "robust to reward changes"), Boey (+0.002/очко на раннем этапе, последние 10% шагов на sparse дали заметный выигрыш), Bansal (500 итераций), AlphaStar pseudo-rewards (затухание по времени эпизода: x0.5 после 8 мин, ещё x0.5 после 16, 0 после 24; веса policy/baseline 4.0/1.0 и 6.0/1.0), OpenAI Five (`0.6^(T/10 мин)`, `team spirit 0.3 -> 0.8`). RLIAYN (Lux S1, 2-е): чистый sparse с нуля дал максимум Elo ~1200 за дни - dense был необходим; Toad Brigade наоборот сработал shaped -> sparse. Универсального правила нет.
- При изменении shaping значения V нестационарны: нужен value normalizer (running mean/std, как в VPT), осторожность с V-trace/GAE бутстрапом.

### 5.5. Value warmup [V + вывод]

Подтверждённые факты: JSRL (случайный critic портит хорошую политику; critic warm-up на 100k шагов); VPT (zero-init value head, value normalization, KL как страховка, пока critic не обучен: "KL prevents making optimization steps that change the policy too much, especially early when the value function has not been optimized yet"); Unplugged (`V^beta` можно обучить офлайн). Andrychowicz 2020 ("What Matters in On-Policy RL", непрерывное управление): инициализация последнего слоя политики сильно влияет; всегда нормализовать наблюдения и проверять нормализацию value; применимость к дискретным/composite action spaces ограничена [вывод]. Primacy bias (Nikishin 2022): периодический reset последних слоёв; для on-policy APPO без replay прямой применимости нет, но идея `reset_value_head` перед RL после долгого BC разумна [вывод].

Предлагаемая процедура [вывод на базе JSRL + VPT + Unplugged]:
- **V0** (опционально): value head офлайн на MC/lambda-returns реплеев при замороженных encoder и policy (`V^beta` - значение политики людей/скрипта, не текущей, поэтому нужен V1);
- **V1**: policy заморожена (`policy_lr = 0`), workers играют BC-политикой против целевого пула, learner обучает только value (V-trace/GAE-таргеты); длительность >= 100k env steps (JSRL) и до плато explained variance (> 0.5 как эвристика);
- **V2**: размораживание политики с линейным LR warmup (0 -> lr за 1-5% шагов) + KL к BC; как у OpenAI Five после surgery (LR=0 первые часы, чтобы Adam подстроился).

### 5.6. Смена архитектуры и пространств посреди соревнования [V]

| Ситуация | Метод |
|---|---|
| Та же I/O, шире/глубже сеть | Net2Net или surgery с точным сохранением функции |
| Новые входные признаки | нулевая инициализация новых входных весов `[W | 0]` (OpenAI Five Eq. 9) |
| Новые действия | zero-init новых логитов + маска/annealing включения, либо distillation |
| Радикальная смена encoder/архитектуры (CNN -> transformer, иной LSTM) | policy distillation + kickstarting (Toad Brigade chain, QDagger) |
| Правила среды | annealing доли игр с новой средой 0 -> 100% |
| Нужно удалить параметры/признаки | surgery не умеет; оставить deprecated-входы константами или distillation |

- **OpenAI Five surgery** (Appendix B): цель `pi_hat(o) = pi(o)`; расширение слоя `W1_hat = [W1 | R()]`, `B1_hat = [B1; R()]`, `W2_hat = [W2; 0]`; расширение LSTM 2048 -> 4096 - только маленькие случайные веса с эмпирически подобранным масштабом ("highest scale which did not noticeably decrease TrueSkill"); новые входы `[W | 0]`; изменения среды/действий - annealing 0 -> 100% с откатом при просадке TrueSkill; **LR = 0 первые часы после surgery** (моменты Adam ломаются при смене формы).
- **Net2Net** (Chen 2015): Net2WiderNet `U_{k,j} = (1/c_j) W_{g(k), g(j)}` с шумом на копиях (иначе дубликаты "слипаются"); Net2DeeperNet - слой с identity-инициализацией; для рекуррентных/attention слоёв рецепта нет [вывод].
- **Distillation в новую сеть**: `L = L_APPO + lambda_k KL(pi_old || pi_new) [+ c_v MSE(V_new, V_old)]`, lambda_0 = 1, линейно -> 0 за 10-20% бюджета; опционально QDagger-pretrain на данных teacher.
- **Чек-лист resume с изменёнными пространствами** [вывод]: версионировать `ActionSpec`/`CompositeDist`; новый head - zero-init весов и bias около -10 (почти нулевая вероятность) или выключенная маска до включения; новые наблюдения - в конец, `W_new_cols = 0`, нейтральная инициализация нормализаторов; сброс Adam + `lr=0` на N шагов + warmup; проверка эквивалентности на фиксированном наборе состояний (`max|logits_new - logits_old| < eps` или `KL < eps`); не менять hidden size LSTM без surgery; **пересчитать матрицу рейтингов** (после смены среды старые рейтинги несопоставимы - OpenAI Five считает TrueSkill на финальной среде, "biased against earlier models").
- **Reincarnating RL** [V]: хранить в CheckpointManager не только weights+optimizer, но и `NetworkConfig`, версию encoder-а, небольшой "teacher dataset" (obs, teacher logits, value) для QDagger-pretrain и eval-манифест для проверки отсутствия регресса после миграции.

### 6.2. Инфраструктура, железо, график

- **Одной персональной машины хватало для топ-1/2**: Toad Brigade (8 ядер/16 потоков, 2 GPU, ~4 месяца "overnight most nights"; конкурент RLIAYN оценил ~20 дней суммарного обучения [оценка конкурента]); Frog Parade (Ryzen 9950X + RTX 3090 + 2070S, ~8 дней, ~300M игровых шагов, плато к ~200M); Boey (RTX 4090 + Ryzen 7950x, 58B шагов за 8 дней, JAX ~80k SPS); 3Comets (Lux S3, 14-е: 1x4090, 15 дней, ~$500 на все эксперименты); RLIAYN (2080Ti, ~4 дня, ~300 steps/s).
- **Большие CPU-кластеры нужны там, где среда медленная**: GRF (SaltyFish 1000-2500 ядер, TamakEri ~4000 CPU + ~20 GPU в последние 3 дня, финальный агент ~700k игр), Hungry Geese 3rd (vast.ai, 12x1080Ti).
- **Скорость симулятора - главный рычаг**: JS-движок Lux S1 ~300 steps/s (80% времени в env.step); Rust 110k steps/s (Frog Parade); JAX 80k SPS (Boey). Все победители S3 писали свой быстрый симулятор.
- **Что дало больше всего**: масштаб (время и размер сети: "the biggest difference between the two approaches is scale" - RLIAYN; Boey: "должна была быть модель 10M+"); frozen teacher + KL (**у всех** RL-победителей); короткий dense shaping, затем sparse zero-sum; BC как дешёвый способ выбрать архитектуру до дорогого RL (RLIAYN, FLG, nosound).
- **Приёмы Flat Neurons / FLG, полезные APPO** [V по writeups]: dynamic reward scaling (скользящее среднее returns по ~5000 батчей, returns в [-5, 5]); dynamic entropy (target entropy на голову линейно падает за 100M шагов, коэффициент подстраивается автоматически); teacher baseline loss; апсэмплинг редких фаз отдельным актором (FLG, spawn/bid ~1% шагов); `torch.compile` ~1.5x; bfloat16.
- **Ограничения инференса диктуют архитектуру**: Lux S1 ~2 с/ход, Lux S2 только CPU и часто 1 ядро (FLG не смог поставить onnxruntime), Lux S3 лимит 100MB; закладывать бюджет inference (latency) в eval.
- **Self-play схема победителей** (раздел 0.1 п.2); EcoBangBang: 50+ дней RL не работало, заработало после перехода на zero-sum baseline и удаления UPGO-loss (его величина на порядок превышала остальные в дашборде).

### 6.3. Как выбирали финальный сабмит

- Kaggle-ladder шумный: GRF - одинаковые агенты расходились на ~90 очков за неделю (Raw Beast); Halite - из 22 сабмитов Tom 16 заняли бы 1-е место; Kore - "ранг был нестабилен"; Lux S3 - играют только **последние 2 сабмита**.
- Практика топов: локальные турниры - WeKick (local ELO LB, "ELO not fully transitive"), Raw Beast (внутренний LB из разнообразных агентов: rules, публичные, клоны, RL), Hungry Geese 3rd ("Coliseum": стадия 1 - 224 матча против стандартного агента ~LB1200, отсев при win-rate < 0.55; стадия 2 - TrueSkill в пуле прошедших), Raine Force (Halite: таблицы head-to-head против топ-5), Toad Brigade (hall_of_fame архив сабмитов).
- **Flat Neurons**: два агента в одном сабмите (слабый 85% партий, сильный 15%), логирование `is_strong`, win-rate по `enemy_submission_id`; цель - не отдавать сильную политику IL-командам, копирующим реплеи лидеров. IL-конкуренты используют ваши ladder-реплеи, публичная лига "протекает" (aDg4b 3-е место обучался на реплеях Frog Parade и Flat Neurons).
- Не принимать решений по <~100 эпизодам на сабмит (моя эвристика [не подтверждено]).

## 7. Мониторинг лиги

### 7.1. Каталог метрик (по CleanRL, PufferLib 3.0, Sample Factory, RLlib) [V по исходникам/документации]

- **CleanRL**: `charts/episodic_return`, `episodic_length`, `learning_rate`, `SPS`; `losses/value_loss`, `policy_loss`, `entropy`, `old_approx_kl`, `approx_kl`, `clipfrac`, `explained_variance`.
- **PufferLib 3.0**: `SPS`, `agent_steps`, `uptime`, `epoch`; `losses/*` (+ `importance` = среднее ratio); `performance/*` (профиль: eval, env, train, copy...); `environment/*` (статистика из `info` среды - сюда естественно класть win-rate). Neptune-логгер больше не актуален.
- **Sample Factory** (самый полный для async/IMPALA): `train/` loss-термы, `kl_loss`, `grad_norm`, `kl_divergence(_max)`, `fraction_clipped`, `ratio_min/mean/max`, `adv_min/max/std`, `value_delta`, `valids_fraction`, `same_policy_fraction`, `adam_max_second_moment`, `returns_running_mean/std`, **`version_diff_min|avg|max` (policy lag)**; рекомендованный диапазон lag "keep below 20-30 SGD steps"; оценка lag = `(num_epochs * num_workers * envs_per_worker * agents_per_env * rollout) / batch_size`; `max_policy_lag` обнуляет `valids` для устаревших сэмплов; PBT ранжирует по "true objective".
- **RLlib**: `env_runners/episode_return_mean`, `learners/policy_loss, vf_loss, entropy, curr_kl_coeff, mean_kl_loss`, MetricsLogger (`reduce = mean/sum/max/min/ema/lifetime_sum`, `with_throughput=True`).
- Что логировали победители: Frog Parade - loss-термы, средние очки, частоты действий, win-rate против предыдущей лучшей модели; EcoBangBang - величины компонентов loss; Flat Neurons - real-time win-rate против старых версий и teacher; Hungry Geese 3rd - win-rate против эталона и TrueSkill в Slack.

### 7.2. Чек-лист для Colosseum (комбинация источников) [рекомендация]

Learner, на агента (`agent/<id>/...`):
1. Оптимизация: policy_loss, value_loss, entropy (и target entropy, если есть контроллер), approx_kl (+max), clip_fraction, ratio min/mean/max, explained_variance, grad_norm (до/после clip), lr, adam_max_second_moment.
2. V-trace/off-policy: rho mean/min/max, доля клипнутых rho и c, `log_rho`, **ESS = (sum rho)^2 / sum rho^2** на chunk, **policy lag (min/avg/max, в версиях)**, доля отброшенных chunk.
3. Advantages/returns: mean/std/min/max до нормализации, returns mean/std, value mean, valids_fraction.
4. Teacher/kickstart: KL(teacher || student), текущая lambda/rho, **вклад каждого loss-слагаемого в total** (stacked "loss composition").
5. Для LSTM: нормы hidden, grad norm по времени; для composite actions: entropy и KL на каждую голову.
Throughput/система: learner SPS, workers env-steps/s, inference latency, **queue depth по агенту**, **chunk age**, weight push/pull lag (версии и секунды), GPU/CPU util, число живых workers/learners, drop count, профиль env.step / forward / transport.
Лига: доли матчей self-play / arena / historical / anchors, распределение выбора оппонентов, win/draw/loss и return по агентам; Elo/TrueSkill (mu, sigma) во времени; payoff matrix с CI; min win-rate vs past; win-rate vs anchors; Nash-веса пула.
Алармы: NaN loss, entropy collapse, approx_kl > 0.1 долго, clip_fraction > 0.5, explained_variance < 0 долго, policy_lag > 20-30, queue depth монотонно растёт (learner не успевает) или равна 0 (workers не успевают), win-rate vs frozen baseline падает.

### 7.3. Диагностики лиг из первоисточников [V]

- **AlphaStar**: Elo всех игроков во времени (якорь Elite bot = 0), Nash-распределение лиги во времени (вес у недавних игроков = нет цикличности и забывания), min win-rate против прошлых версий, состав лиги по test Elo/RPP, payoff-matrix в coordinator.
- **OpenAI Five**: TrueSkill во времени (random = 0); **распределение выбора оппонентов** (Fig. 27: узкое = быстрый рост, широкое = медленный); staleness `M - N`: замедление при +8 версий, целевое 0-1; "high quality data matters more than compute".
- **FTW**: online Elo популяции, эволюция гиперпараметров и внутренних наград по популяции.

### 7.4. Дашборд лиги (проектное предложение) [рекомендация]

Панели: A) здоровье обучения по агенту + loss composition; B) throughput и очереди; C) рейтинги во времени с якорем (frozen baseline = 0); D) **payoff heatmap** (строки/столбцы упорядочены по рейтингу, цвет - win-rate, серым - мало данных, в tooltip Wilson CI и число матчей; подсветка ячеек, где слабый бьёт сильного); E) win-rate по оппонентам во времени и min win-rate vs past; F) распределение выбора оппонентов (stacked area); G) Nash-веса пула и exploiter best-response; H) lineage-граф (кто от кого форкнут/дистиллирован, цвет = рейтинг); I) pulse-check: win-rate vs scripted/baseline/best/teacher каждые K шагов; J) поведенческие метрики (частоты действий, доля no-op, "agent gives up", replays худших/лучших матчей); K) ladder-панель (score по сабмитам, win-rate по `enemy_submission_id`).

    loss: cross_entropy                       # cross_entropy | mse (composite: per-head)
  value_warmup:                               # обязательная стадия между BC и RL
    enabled: true
    policy_lr: 0.0                            # политика заморожена
    min_env_steps: 100000
    until_explained_variance: 0.5
    reset_value_head: true                    # zero-init (VPT)

    teacher: checkpoints/bc_final.pt          # BC | scripted | prev_checkpoint | path

    # альтернативы расписания: linear (за 10-20% бюджета), performance_weaning (QDagger)
    replaces_entropy_bonus: true              # как в VPT
    teacher_logits_in_chunk: false            # true: считать на worker

      enabled: false
      predicate: examples.my_game.bots.is_critical_state

  distill_from:                               # смена архитектуры
    teacher: checkpoints/old_arch_best.pt
    lambda: {start: 1.0, schedule: linear, frac_of_budget: 0.15}

# ---------- reward ----------

  team_spirit: {start: 0.3, end: 0.8, over_frac: 0.5}

    - name: territory

  value_normalization: running_mean_std

# ---------- league ----------

  roster:                                    # единая модель оппонентов
    - {id: main_a, type: trainable, config: agents/a.yaml}
    - {id: main_b, type: trainable, config: agents/b.yaml}   # другая архитектура/encoder
    - {id: bc_v0,  type: frozen,    checkpoint: ckpts/bc_final.pt, anchor: true}
    - {id: rush,   type: scripted,  class: bots.RushBot, anchor: true}
    - {id: turtle, type: scripted,  class: bots.TurtleBot, anchor: true}
  snapshots:
    interval_updates: 1000
    keep: {recent: 10, log_spaced_older: 10, protect_best: 3}   # не FIFO
  opponent_sampling:                         # для каждого trainable-агента
    mix: {self_play: 0.35, pfsp: 0.50, verification: 0.15}
    pfsp: {weighting: squared, variance_for_struggling: true, winrate_window_decay: 0.99}
    fallback_when_winrate_below: 0.3         # откат на исторические чекпоинты оппонента

    anchors: {match_fraction: 0.15, floor_prob_each: 0.03, decay_to_zero: false}
  match_types:

    self:  {weight: 0.2}                     # все слоты = latest
    arena: {weight: 0.3, trainable_per_match: [2, 3], fill_rest: pfsp}
  exploiters:
    main_exploiter:
      enabled: false
      target: main_a
      init: bc_v0                            # inherit | bc_v0 | scratch
      snapshot_when: {min_winrate_vs_target: 0.7, timeout_updates: 2000}
      reset_after_snapshot: true
    league_exploiter: {enabled: false, reset_prob: 0.25}
  forgetting_guard:
    min_winrate_vs_past: 0.7                 # ниже порога -> больше verification, выше KL якорь
    action: raise_verification_share

# ---------- рейтинги ----------
rating:
  store: sqlite://league.db
  online: {system: openskill_plackett_luce, mu: 25, sigma: 8.333, tau: 0.0833}
  batch:                                      # источник для отбора
    system: bradley_terry_mle
    refit_every_min: 10

    ci: {method: bootstrap_by_match, replicas: 1000}
  seat_bias: {enabled: true}                  # параметр b_seat
  diagnostics: {intransitivity: true, nash_average: true, alpharank: false}

# ---------- отбор / eval ----------
selection:

  procedure:
    - successive_halving: {games_round1: 100, keep: 0.5, double_each_round: true}
    - holdout_recheck: {games: 1000, fresh_seeds: true, rotate_seats: true}
    - metrics: [winrate_ci, min_winrate_over_opponents, nash_value]
