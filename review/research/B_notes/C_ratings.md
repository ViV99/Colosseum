## 0. TL;DR для Colosseum (детали ниже)

1. Для оценки **пула фиксированных (frozen) чекпоинтов** онлайн-Elo — плохой инструмент: результат зависит от порядка игр и K, шум на порядок больше, чем у batch Bradley–Terry MLE при тех же играх [SIM: K=32, 2000 игр, std разности рейтингов 78 Elo против 7.8 у BT-MLE]. Именно поэтому LMSYS/Chatbot Arena ушёл с online Elo на BT MLE + CI. Рекомендация: **batch BT-MLE (с анкором и L2-регуляризацией) + bootstrap по матчам**, онлайн-Elo оставить только как "живой" индикатор для дашборда.
2. Для **N-игроков/FFA** — либо сводить к парным исходам (как уже делает `eval.py`) и считать BT, либо Plackett–Luce (OpenSkill `PlackettLuce`, `choix.ilsr_rankings`). TrueSkill/OpenSkill удобны онлайн, дают (mu, sigma) и поддерживают ranks с ничьими; OpenSkill на порядки проще лицензионно (MIT) и быстрее, `trueskill` — эталон, но давно не обновляется.
3. **Нетранзитивность** (RPS) Elo/BT не видят вообще (все 3 агента получают одинаковый рейтинг и предсказывают 50%). Для лиги нужны: Nash averaging / α-Rank / "spinning top"-разложение как *диагностика* и для выбора "сабмит-смеси", а PFSP уже сам по себе — защита от forgetting.
4. **Выбор лучшего чекпоинта** — это задача best-arm identification с winner's curse. [SIM] При K=20 кандидатах и n=400 играх на каждого, если все равны по силе, выбранный "лучший" завышен в среднем на ~32 Elo; при K=100 — ~44 Elo. Лечится: отдельный hold-out-матч (свежие сиды/оппоненты) для финалиста, successive halving, симультанные CI (Bonferroni/χ²-множество как в Arena).
5. **Gating**: AlphaGo Zero — 55% за ~400 игр; KataGo — ≥100/200; AlphaZero — без gating. [SIM] Порог 55%/400 игр пропускает кандидата с истинным +35 Elo только в 52% случаев, а с +10 Elo — в 8%. SPRT (fishtest) даёт контролируемые α/β и в среднем меньше игр. Для Colosseum (PFSP-лига с "FIFO-снапшотами") gating не обязателен: AlphaStar снапшотит по расписанию, а отбор делается на этапе submit.
6. Готовые библиотеки: `openskill` (PlackettLuce, FFA, ties, `predict_*`), `trueskill`, `choix` (BT/Plackett–Luce MLE, EP), `evalica` (Rust, BT/Elo/…, bootstrap), `open_spiel.python.egt.alpharank`. API-примеры проверены (раздел 5).

## 1. Системы рейтинга

### 1.1 Elo

Формулы [V: https://www.chessprogramming.org/Match_Statistics, https://arxiv.org/abs/1806.02643 (ar5iv https://ar5iv.labs.arxiv.org/html/1806.02643)]:
- Ожидаемый счёт: `E_A = 1 / (1 + 10^{-(R_A - R_B)/400})`; обратная: `Δ = 400·log10(E/(1−E))`.
- Эквивалентно логистике `σ(α(r_A − r_B))`, `α = ln(10)/400 ≈ 0.00576`.
- Обновление: `R' = R + K·(S − E)`, S ∈ {1, 0.5, 0} (общепринятое; пересказ https://metricgate.com/docs/elo-rating/ [S]).
- Полезные соответствия [SIM, sim2]: win rate 55% ↔ +34.9 Elo; 60% ↔ +70.4 Elo; 75% ↔ +191 Elo.

K-факторы в реальных системах:
- FIDE: K=40 для новых (<30 партий), K=20 пока рейтинг <2400, K=10 после достижения 2400; кап `K·n ≤ 700` за период; правило 400 пунктов [V: https://handbook.fide.com/chapter/B022024].
- FastChat/LMSYS online Elo: K=4, base 10, scale 400, init 1000 [V: https://raw.githubusercontent.com/lm-sys/FastChat/main/fastchat/serve/monitor/rating_systems.py — `compute_elo(df, k=4.0, base=10.0, init_rating=1000.0, scale=400.0)`]. `evalica.elo` повторяет эти дефолты (k=4, initial=1000, scale=400, base=10) [V: проверено `inspect.signature`, раздел 5].
- AlphaStar: Elo внутри лиги, Elo встроенного Elite-бота зафиксирован = 0, шкала 400 [V: https://storage.googleapis.com/deepmind-media/research/alphastar/AlphaStar_unformatted.pdf — "Metrics used in Figures"; сама формула в извлечённом тексте повреждена, см. 4.3].

**Elo как онлайн-SGD для BT.** Обновление Elo — один шаг стохастического градиентного подъёма по BT-log-likelihood; K — learning rate [V-ish: Király & Qian, https://arxiv.org/abs/1701.08055 "Élő system is very closely related to the Bradley–Terry models"; формулировка "Elo=online SGD" — пересказ поисковой выдачи, [S]]. Следствия:
- K большой → быстрая адаптация, но стационарный шум (см. таблицу ниже).
- K малый → медленная сходимость и "память" о давно изменившихся игроках.
- Нет понятия неопределённости на игрока → нет CI.
- Результат зависит от порядка игр (non-commutative). Работа "Elo Uncovered" показывает на LLM: нетранзитивность, волатильность, чувствительность к K и порядку [S: https://arxiv.org/abs/2311.17295 — по пересказу WebFetch abstract].

**Шум онлайн-Elo vs BT-MLE** [SIM, sim3.py]: два равных игрока, 2000 игр, std итоговой разности рейтингов (400 прогонов):

| K | std(rA−rB), Elo |
|---|---|
| 4 | 25.6 |
| 8 | 39.0 |
| 16 | 51.3 |
| 32 | 77.7 |
| 64 | 113.8 |

Для сравнения std BT-MLE при N играх (p=0.5), `400/ln10·√(4/N)`: N=200 → 24.6; N=1000 → 11.0; N=2000 → 7.8; N=10000 → 3.5 [SIM/аналитически]. То есть при K≥16 на практике онлайн-Elo шумит в 6–15 раз сильнее. Это объясняет решение LMSYS.

### 1.2 Glicko / Glicko-2

Алгоритм (Glickman, https://www.glicko.net/glicko/glicko2.pdf, версия 22.03.2022) [V — извлечён текст PDF]:
- У игрока: рейтинг r, rating deviation RD, volatility σ. Новый игрок: r=1500, RD=350, σ=0.06 (σ "зависит от приложения").
- Шкала: `μ = (r−1500)/173.7178`, `φ = RD/173.7178`.
- `g(φ) = 1/√(1 + 3φ²/π²)`, `E(μ,μj,φj) = 1/(1+exp(−g(φj)(μ−μj)))`.
- `v = [Σ g(φj)² E (1−E)]^{-1}`, `Δ = v·Σ g(φj)(sj − E)`.
- Новая волатильность σ' — итерация (Illinois algorithm) для `f(x) = e^x(Δ²−φ²−v−e^x)/(2(φ²+v+e^x)²) − (x−a)/τ²`, `a=ln σ²`, ε=1e-6.
- `φ* = √(φ²+σ'²)`, `φ' = 1/√(1/φ*² + 1/v)`, `μ' = μ + φ'²·Σ g(φj)(sj−E)`.
- Системная константа **τ ∈ [0.3, 1.2]** (разумно), "даже 0.2" если ожидаются очень маловероятные результаты.
- **Рейтинговый период**: игры в периоде считаются одновременными; система работает лучше при ≥10–15 играх на игрока в периоде. Если игрок не играл — растёт только RD.
- 95% интервал: `r ± 2·RD`.

Вывод [МОЁ]: Glicko-2 заточен под 1v1 с рейтинговыми периодами; для стрима матчей из распределённых workers и N-игроков неудобен. Полезна лишь идея RD (неопределённость) — её даёт и TrueSkill/OpenSkill (sigma). Нативной поддержки FFA нет [не подтверждено в первоисточнике, но алгоритм выше определён только для парных результатов sj].

### 1.3 TrueSkill (Microsoft Research)

- Описание [V: https://www.microsoft.com/en-us/research/project/trueskill-ranking-system/]: пара (μ, σ); консервативная оценка `μ − 3σ` (1%-квантиль); поддержка многих игроков и команд; уменьшение σ с числом игр; **сходимость: ~3 игры в 8-игроковом FFA, ~12 в 1v1**, больше в командных режимах.
- Дефолты в `trueskill` (python) [V: https://trueskill.org/ + проверено `print(trueskill.MU, ...)`]: MU=25, SIGMA=25/3≈8.333, BETA=SIGMA/2≈4.167 ("разрыв навыка β даёт ≈76% вероятности победы" — проверка: Φ(β/(√2β))=Φ(0.707)=0.76), TAU=SIGMA/100≈0.0833 (динамический фактор, "dynamics"), DRAW_PROBABILITY=0.10.
- Первая 1v1-игра между двумя новичками [SIM]: победитель mu 25→29.396 (σ 8.333→7.171), проигравший 25→20.604; те же числа (29.396/7.171) приведены в примере `rate_1vs1` на trueskill.org (там пример с Rating(25) vs Rating(30) — по пересказу WebFetch, точность пересказа [не подтверждена]).
- FFA с ничьёй: `rate([(r,),(r,),(r,),(r,)], ranks=[0,1,1,3])` → mu 31.56, 24.99, 25.01, 18.44 [SIM, t2.py]. Ничья обрабатывается через равные ranks, `draw_probability` калибрует ширину "зоны ничьей".
- Веса частичного участия: `rate(..., weights=...)` [V trueskill.org].
- Для TrueSkill в среде с `tau=0` (как в OpenAI Five) рейтинг "замораживается" по мере роста числа игр — подходит для эвала замороженных референсов, не для движущихся агентов.
- Лицензия/патенты: TrueSkill — торговая марка/патент Microsoft; python-пакет `trueskill` BSD, но коммерческое использование алгоритма — оговорка [не подтверждено; проверять юристом]. Это один из мотивов OpenSkill.

### 1.5 OpenSkill (Weng–Lin)

- Теория: Weng & Lin, "A Bayesian Approximation Method for Online Ranking", JMLR 12 (2011) — аналитические обновления без численного интегрирования, "конкурентны с TrueSkill при гораздо меньших вычислениях" [V: https://jmlr.org/papers/v12/weng11a.html].
- Библиотека `openskill` (Python), статья JOSS 2024 [V abstract: https://arxiv.org/abs/2401.05451]: быстрее и точнее TrueSkill в их тестах (по заявлению авторов; независимо не проверял — [не подтверждено]), поддержка time decay, асимметричных команд.
- Модели [V: https://openskill.me/en/stable/manual.html]: `PlackettLuce` (рекомендуется), `BradleyTerryFull`, `BradleyTerryPart`, `ThurstoneMostellerFull`, `ThurstoneMostellerPart`. "Full" — полные попарные сравнения (точнее, медленнее), "Part" — частичные (только соседи по рангу).
- Сигнатура `PlackettLuce` [V: https://openskill.me/en/stable/api/openskill.models.weng_lin.plackett_luce.html + проверено локально v6.2.0]:
  `mu=25.0, sigma=25/3, beta=25/6, kappa=0.0001, tau=25/300, margin=0.0, limit_sigma=False, balance=False, weight_bounds=(1.0, 2.0)`.
  - `tau` — аддитивная динамика (не даёт sigma упасть до 0); `limit_sigma` — запрещает sigma расти; `balance` — усиливает выбросы; `margin` — порог "впечатляющей" победы.
  - Заметка: `rate(teams, ranks=None, scores=None, weights=None, tau=None, limit_sigma=None)`; ranks — меньше=лучше; равные ranks = ничья.
- Первая 1v1-игра [SIM, t1.py]: PlackettLuce / BradleyTerryFull / BradleyTerryPart дают одинаково mu 25→27.635, sigma 8.333→8.066 (проигравший 22.365); ThurstoneMostellerFull → 29.231 / 7.631 / 20.769. Для сравнения TrueSkill: 29.396 / 7.171. Т.е. OpenSkill PL обновляется заметно **осторожнее** (±2.6 против ±4.4 mu за первую игру) и сигма падает медленнее; это важно для скорости сходимости на малом числе игр. Подтверждено локально.
- FFA: `m.rate([[a],[b],[c],[d]], ranks=[1,2,2,4])` → mu 27.80, 24.69, 24.69, 22.83 [SIM].
- `m.predict_win([[a],[b]])`, `predict_draw`, `predict_rank` — готовые вероятности; `ordinal(z=3.0, alpha=1, target=0)` = `alpha·((mu − z·sigma) + target/alpha)` (для новичка mu−3σ = 0.0) [SIM].

### 1.6 Batch Bradley–Terry MLE (BayesElo, Ordo, Chatbot Arena)

**Модель**: `P(i бьёт j) = 1/(1 + exp(ξ_j − ξ_i))`, ξ — BT-коэффициенты; без потери общности ξ_1=0; в Elo-шкале `rating = 400·ξ/ln(10) + 1000` (log base 10) [V: https://arxiv.org/abs/2403.04132, §4; PDF прочитан].

**Почему LMSYS перешёл с online Elo на BT MLE** [V частично]:
- Блог LMSYS: у них есть вся история игр, а модели "в основном статичны"; BT предполагает фиксированную силу и даёт MLE соответствующей Elo-модели, тогда как online Elo создан для меняющихся игроков (по пересказу WebFetch блога https://lmsys.org/blog/2023-12-07-leaderboard/ [S]). Также CI из bootstrap по онлайн-Elo были слишком широкими.
- Статья Chatbot Arena (https://arxiv.org/abs/2403.04132): "previous evolutions of our online interface have reported ... the Elo score ... We made this change because the BT coefficients are better for the purpose of statistical estimation" [V дословно].
- Оценка: взвешенная (обратные вероятности выбора пары `1/P(A_t)`) логистическая регрессия; MLE асимптотически нормален даже при misspecification, если использовать **sandwich-ковариацию** (Huber 1967, White 1982).
- CI: два способа — pivot bootstrap и sandwich robust SE. По симуляции (Appendix A) они выбрали **sandwich** — меньшие интервалы на больших выборках [V]. Для рангов — одновременное χ²-доверительное множество по sandwich-дисперсии и "approximate ranking" `R_m = 1 + Σ 1{inf C_{m'} > sup C_m}` (гарантия `P(∃m: R_m > rank_m) ≤ α`) [V].
- Адаптивная выборка пар: `P_t(a) ∝ √(Σ̂_aa/n_a) − √(Σ̂_aa/(n_a+1))` (приоритет парам, уменьшающим CI сильнее всего) [V].
- Код FastChat [V: rating_systems.py]: `fit_bt` через `scipy.optimize.minimize(method="L-BFGS-B", maxiter=100, gtol=1e-6)` на уникальных (matchup, outcome) с весами; ничья = 0.5 выигрыша (цель 0.5 в кросс-энтропии); `scale_and_offset`: `ratings*400 + 1000`, затем сдвиг так, чтобы baseline (`mixtral-8x7b-instruct-v0.1`) = 1114 (анкор); `compute_bootstrap_bt`: ресемпл через **multinomial по весам** (`rng.multinomial(n=len(battles), pvals=weights/weights.sum(), size=num_round)`) и параллельный `fit_bt`; CI = квантили 2.5/97.5 бутстрэп-распределения (в `elo_analysis.py`) [V через пересказ].
- Важное замечание для N-игроков [МОЁ]: bootstrap надо делать **по матчам (кластерам)**, а не по парным исходам, если один матч N-игроков порождает несколько коррелированных пар.

**BayesElo / Ordo** (chess):
- BayesElo использует prior на результаты ("prior=2"?), параметры `eloAdvantage=32.8`, `eloDraw=97.3` по умолчанию [S: https://talkchess.com/viewtopic.php?p=473434 — выдача поиска, не открывал; значение "prior=2" [не подтверждено]]. AlphaZero оценивал Elo через BayesElo (`c_elo=1/400`) [V: https://arxiv.org/pdf/1712.01815, Methods].
- Ordo (Ballicora): без prior, поддерживает "loose anchors", неопределённость преимущества белых и draw-rate, 95% CI [S: https://talkchess.com/viewtopic.php?p=470891].
- Для Colosseum нужны разные "подушки": на ничьи (draw) можно использовать Davidson/Rao–Kupper расширения BT [не подтверждено; в Glickman 2025 работе про ties https://arxiv.org/abs/2505.24783 — не читал].

### 1.7 α-Rank

Источник: Omidshafiei et al., "α-Rank: Multi-Agent Evaluation by Evolution", Sci. Reports 2019; arXiv https://arxiv.org/abs/1903.01373 (PDF прочитан) [V].
- Мета-игра: payoff-таблицы `M^k` из симуляций. Эволюционная модель с конечной популяцией размера m, **Fermi-функция** выбора (4): `P(τ→σ) = (1 + e^{α(f(τ) − f(σ))})^{-1}`; α — "ranking-intensity".
- Марковская цепь над профилями стратегий (∏|S_k| состояний), переходы = fixation probabilities мутанта; ранг = **стационарное распределение π**, "масса" — оценка агента.
- Рекомендация авторов: брать α достаточно большим; эвристика — **sweep α** от малого с экспоненциальным ростом до сходимости ранга. В эвале m=50.
- Плюсы vs Nash: полиномиально от числа профилей (Nash для general-sum — PPAD-complete), единственное решение, ловит циклы (Markov–Conley chains), для RPS даёт равную массу 3 стратегиям. [V]
- Минусы [МОЁ]: размер таблицы растёт как n^N для N игроков (профили), нужны payoff-ы для всех профилей; чувствителен к масштабу payoff-ов и α.
- OpenSpiel (проверено, v2.0.2): `from open_spiel.python.egt import alpharank`; `alpharank.compute(payoff_tables, m=50, alpha=100, use_local_selection_model=True, verbose=False, use_inf_alpha=False, inf_alpha_eps=0.01)` → `(rhos, rho_m, pi, num_profiles, num_strats_per_population)`; `sweep_pi_vs_alpha(payoff_tables, strat_labels=None, warm_start_alpha=None, visualize=False, return_alpha=False, m=50, rtol=1e-5, atol=1e-8, ...)`. Для работы импорта нужны `matplotlib` и `networkx` (иначе ImportError на `alpharank_visualizer`) [SIM, t4.py]. Док: https://github.com/google-deepmind/open_spiel/blob/master/docs/alpha_rank.md.
- Пример [SIM]: RPS → π=(1/3,1/3,1/3); RPS + слабый агент W (проигрывает всем) → π=(0.333,0.333,0.333,0.000).

### 1.8 Nash averaging (Balduzzi et al. 2018, "Re-evaluating Evaluation")

Источник: https://arxiv.org/abs/1806.02643, ar5iv https://ar5iv.labs.arxiv.org/html/1806.02643 [V].
- Elo: `p̂_ij = σ(α r_i − α r_j)`, α = ln10/400. "Elo ... is meaningless — it has no predictive power — in cyclic games like RPS" (все получают одинаковый рейтинг, предсказание 50%).
- Hodge-разложение антисимметричной матрицы `A` (логиты побед): `A = grad(r) + rot(A)`; дивергенция (`div(A)=row mean`) восстанавливает Elo-подобный рейтинг; curl=0 ⇔ матрица транзитивна ("disc decomposition": transitive disc + cyclic part).
- Nash averaging: мета-игра с выплатой `p^T A q`; берётся **max-entropy Nash** `p*`; Nash average `n_A = A p*`.
- Теорема 1: инвариантность к избыточности (клоны не меняют результат — масса клона делится поровну), непрерывность, интерпретируемость (для чисто циклической матрицы — uniform; для чисто транзитивной — масса на лучшем).
- "Elo can be inflated by instantiating many copies of an agent it beats" [V].
- Демонстрация [SIM, sim3.py; Elo = row-mean логитов, как div(A)]: агенты R,P,S (циклические, 75% побед друг над другом) + W (проигрывает всем 90%). Elo(R)=95.4; после добавления 10 клонов W Elo(R)=299.9 (инфляция в 3 раза!); Nash p = (1/3,1/3,1/3,0,…) и Nash average для R,P,S = 0 в обоих случаях — инвариантно. Это обоснование того, почему "добавление слабых sparring-ботов" в пул не должно влиять на выбор лучшего.
- Ограничения [МОЁ]: определён для 2-игроковых симметричных zero-sum (антисимметричная A); N-игроки требуют редукции к парам или других концепций.

### 1.9 Rectified Nash / "spinning top" (Balduzzi et al. 2019)

Источник: "Open-ended Learning in Symmetric Zero-sum Games", ICML 2019, https://arxiv.org/abs/1901.08106 (ar5iv: https://ar5iv.labs.arxiv.org/html/1901.08106) [V — прочитан ar5iv; arXiv-номер 1901.08106, не 1901.01753 как иногда ошибочно цитируется].
- Функциональные игры (FFG) раскладываются ортогонально: **transitive ⊕ cyclic** (Thm 1). Transitive: `φ(v,w) = f(v) − f(w)`; cyclic: `∫ φ(v,w) dw = 0`. Форма "волчка" (spinning top): сила растёт к вершине (транзитивная ось), но есть циклическое "кольцо" (стратегическая нетранзитивность) на каждом уровне.
- Алгоритмы: **PSRO_N** (best response к Nash-смеси популяции); **PSRO_rN** (Rectified Nash response) — каждый агент из support Nash тренируется только против тех, кого он уже бьёт, цель `Σ_i p_t[i]·⌊φ_{w_i}(·)⌋_+`, `⌊x⌋_+ = max(0,x)` — game-theoretic niching.
- **Effective diversity**: `d(P) = pᵀ ⌊A_P⌋_+ p = Σ_ij ⌊φ(w_i,w_j)⌋_+ p_i p_j` (объём ℓ₁,₁ агентов под Nash).
- **Relative population performance**: `v(P,Q) = pᵀ A_{P,Q} q` (Nash мета-игры между популяциями; Def 3): если выпуклая оболочка одной популяции содержит другую, v ≥ 0 против любой третьей — транзитивный прогресс на уровне популяции, несмотря на нетранзитивность агентов. AlphaStar использует то же как метрику RPP [V].
- Замечание про Elo: для монотонных игр `P(v≻w)=σ(f(v)−f(w))` градиент затухает при большом разрыве → мотивирует self-play вместо фиксированных оппонентов [V].

## 2. Рейтинги исторических чекпоинтов

### 2.1 Что делает OpenAI Five (прямой прецедент)

Источник: arXiv https://arxiv.org/abs/1912.06680 (PDF прочитан, Appendix J "TrueSkill: Evaluating a Dota 2 Agent Automatically", Appendix N "Self-play") [V].
- TrueSkill-окружение: `σ=25/3, β=σ/2, τ=0.0, draw_probability=0.02`; μ выровнены так, что случайный агент = 0.
- **Пул из 83 референсных агентов** (TrueSkill 0…254), оценивается один раз играми между референсами.
- Тестируемый агент играет только с референсами **рядом по силе**: не дальше 10 TrueSkill (что в тексте соответствует winrate <15% или >85%).
- После игры обновляется TrueSkill тестируемого, **референс рассматривается как константа**; после 750 игр версия логируется; **новый агент инициализируется μ предыдущего агента** (наследование от родителя!). Обновление примерно раз в 2 часа.
- Проблема: метрика-инфляция для новых агентов, обучавшихся на новейшей версии игры (patch drift).
- Self-play: 80% игр против последних параметров, 20% против прошлых; прошлые оппоненты сэмплируются softmax по "quality score" `q_i`: `p_i ∝ e^{q_i}`; каждые 10 итераций текущий агент добавляется в пул с q = max существующих; если текущий победил прошлого, `q_i ← q_i − η/(N p_i)`, η=0.01 [V].
- Расхождение, которое стоит учесть: в тексте статьи "разница ≈8.3 TrueSkill ≈ 80% winrate" и "10 пунктов ≈ 85/15%". При β=σ/2=4.167 формула `Φ(Δ/(√2·β))` даёт для Δ=8.3 ≈ **92%**, для Δ=10 ≈ 95.5% [SIM/аналитика]. Либо статья использует другую шкалу β, либо приближение грубое — [не подтверждено], не копировать эти числа без проверки.

### 2.2 Заморозка рейтинга и инициализация нового чекпоинта

Практика (источники выше + [МОЁ]):
1. **Frozen-референсы с замороженными рейтингами** (OpenAI Five): рейтинг нового агента оценивается относительно "якорного" пула, пул не обновляется → нет дрейфа, чисто калибровка одного игрока (одномерная оценка; можно использовать OpenSkill/TrueSkill с `tau=0` либо BT-MLE одного параметра при фиксированных остальных).
2. **Наследование** рейтинга родителя как prior: `mu_init = mu_parent`, `sigma_init = sigma_parent` (или слегка увеличенная, чтобы допустить скачок). OpenAI Five — наследует μ [V]; логика: чекпоинты одной линии близки по силе; быстрее сходимость, меньше игр для калибровки.
3. **Prior на первую игру**: если родителя нет — `Rating()` по умолчанию (μ=25, σ=25/3) или рейтинг сида/бота.
4. [МОЁ] Для BT-MLE: добавить слабый гауссов prior вокруг рейтинга родителя (L2 к `ξ_parent`, а не к 0) — тогда новый чекпоинт без игр получает рейтинг родителя, а с ростом числа игр данные доминируют. Это эквивалентно регуляризации в Arena (`reg`), только вокруг родителя. Прямого прецедента в источниках не нашёл [не подтверждено].

### 2.3 Дрейф/инфляция Elo в self-play

- Классический Elo (симметричный K) **нулесуммовый**: сумма рейтингов сохраняется при обновлении; инфляция/дефляция возникает при входе/выходе игроков и неоднородности K (FIDE: новички входят с фиксированным рейтингом и в среднем теряют очки, более слабые чаще уходят) [S: https://talkchess.com/viewtopic.php?p=282912 и поисковая выдача про chess.com; не открывал].
- В пуле чекпоинтов, где растёт сила, новые чекпоинты "входят" в систему с рейтингом родителя, а реальная сила выше → очки перетекают от старых к новым только через игры; если пул окнный (играют только с последними N), **шкала сжимается**.
- [SIM, sim4.py] 100 чекпоинтов, каждый на +10 Elo сильнее предыдущего (истинный диапазон 990 Elo), по 40 игр на новый чекпоинт, оппоненты — случайные предыдущие. Результаты (среднее по 5 сидам; RMSE оценки относительно истины, оценённый диапазон последнего чекпоинта):

| Схема | окно оппонентов | RMSE, Elo | оценка диапазона |
|---|---|---|---|
| online Elo K=16, оба обновляются | все | 69.4 | 892 |
| online Elo K=16 | последние 10 | 147.5 | 763 |
| online Elo K=32 | все | 72.9 | 960 |
| online Elo K=32 | последние 10 | 135.9 | 821 |
| frozen-оппоненты K=16 (обновляется только новый) | все | 82.4 | 871 |
| frozen K=16 | последние 10 | 101.4 | 829 |
| frozen K=32 | все | 72.5 | 929 |
| frozen K=32 | последние 10 | 91.6 | 923 |
| batch BT-MLE | все | 71.8 | 955 |
| batch BT-MLE | последние 10 | 82.0 | 926 |

Вывод [SIM, ограничения: одна конфигурация, 5 сидов, G=40]: при локальных матчингах (окно) онлайн-Elo **сжимает шкалу** (763–821 вместо 990) и вдвое увеличивает ошибку; batch BT и frozen-оппоненты устойчивее. Ошибка цепочки накапливается (random-walk) в любом случае — нужны "дальние" связи (случайные игры с далёкими чекпоинтами, как в PFSP-смеси), иначе шкала по цепочке дрейфует.

### 2.4 Нетранзитивность

- Elo/BT предполагает `P(i≻j)=σ(r_i−r_j)` (ранг-1 антисимметрия). На RPS: логиты A циклические, `div(A)=0`, рейтинги равны [V: Balduzzi 2018].
- Диагностика цикличности [МОЁ + V]: построить антисимметричную матрицу логитов `A_ij = logit(P_ij)`; `r = row-mean(A)` (Elo-часть); остаток `A − (r 1ᵀ − 1 rᵀ)` — циклическая часть (Hodge). Доля нормы остатка = индикатор нетранзитивности; если >~ 20–30% — Elo вводит в заблуждение [порог — мой эвристический, не из источника].
- Для лиги: Nash-смесь/α-Rank показывают, какие чекпоинты вообще "нужны" (support) — остальные избыточны.
- AlphaStar: в **высоконетранзитивных** играх "pursuit of mean win-rate might lead to policies that are easy to exploit" → PFSP `f_hard(x)=(1−x)^p` = сглаженная max-min оптимизация [V: AlphaStar PDF].

### 2.5 AlphaStar: метрики для лиги

[V: https://storage.googleapis.com/deepmind-media/research/alphastar/AlphaStar_unformatted.pdf]
- PFSP: `P(B) = f(P[A бьёт B]) / Σ_C f(P[A бьёт C])`; `f_hard(x) = (1−x)^p`; `f_var(x) = x(1−x)` (оппоненты "своего уровня"; для main exploiters и struggling main agents).
- **Relative Population Performance (RPP)**: ожидаемый исход мета-игры двух популяций в Nash: `RPP(P_AB) = Nash(P_AB)_A^T · P_AB · Nash(P_AB)_B` (формула в PDF-текстe частично искажена, смысл — по описанию).
- "Min win-rate vs past" — прокси forgetting.
- Elo ограничен пользовательским якорём (Elite bot = 0); метрики Elo/RPP/forgetting вместе.

## 3. Как надёжно выбрать лучший чекпоинт

### 3.1 Размеры выборок и доверительные интервалы

**Wilson 95% CI** для доли `p̂ = k/n`, z=1.96: `c = (p̂ + z²/2n)/(1+z²/n)`, `h = z·√(p̂(1−p̂)/n + z²/4n²)/(1+z²/n)`, интервал `c ± h`. Перевод границ в Elo через `400·log10(p/(1−p))`.

Полуширина 95% Wilson CI в Elo при p̂=0.5, бинарные исходы [SIM, sim1.py]:

|---|---|

| 100 | 67.7 |
| 200 | 48.0 |
| 400 | 34.0 |
| 1000 | 21.5 |
| 2000 | 15.2 |
| 5000 | 9.6 |
| 10000 | 6.8 |
| 50000 | 3.0 |

`n = ((z_α + z_β)·s / (p − 0.5))²`, `z_α=1.645`, `z_β=0.842`, `s=√(0.25(1−d))`.

**Bootstrap**: ресемплить **матчи** (не пары, не игры внутри матча если они коррелированы), по 1000+ реплик, 2.5/97.5 квантили (FastChat: `bootstrap_df.quantile(0.025/0.975)` [V, elo_analysis.py]). Для агрегированных метрик по нескольким сидам/задачам: stratified bootstrap + IQM (Agarwal et al., NeurIPS 2021 [V abstract: https://arxiv.org/abs/2108.13264]; библиотека `rliable`).

### 3.2 Hold-out / фиксированный benchmark-набор

[МОЁ, с опорой на практику]:
- **Fixed benchmark pool**: небольшой набор замороженных оппонентов (scripted bots + 3–10 исторических чекпоинтов из разных фаз + выбранные эксплойтеры), не используемый в обучении как sparring-partners *или* используемый, но с отдельным held-out подмножеством — иначе selection bias через overfitting к пулу. OpenAI Five: 83 референса, играют только близких по силе (±10 TrueSkill), 750 игр на версию [V].
- Метрики для сабмита: (1) win-rate/score против benchmark с CI; (2) min win-rate против любого оппонента (max-min, как f_hard в PFSP) — устойчивость к эксплойтам; (3) Nash-mixture value против пула (RPP-стиль) [V AlphaStar metrics].
- Свежие сиды окружения и side-swap (round-robin слотов) для финальных матчей.

### 3.3 SPRT (fishtest/Stockfish)

**Определения** [V: van den Bergh, GSPRT: https://www.cantate.be/Fishtest/GSPRT_approximation.pdf; Normalized Elo: https://www.cantate.be/Fishtest/normalized_elo_practical.pdf; Fishtest wiki: https://github.com/official-stockfish/fishtest/wiki/Fishtest-mathematics]:
- Тест H0: φ=φ0 против H1: φ=φ1 (φ — например, ожидаемый счёт или Elo). Мониторится `LLR = L(θ̂₁,x) − L(θ̂₀,x)` (в GSPRT θ̂_i — MLE при ограничении φ(θ̂_i)=φ_i).
- **Границы**: стоп, когда LLR выходит из `[log(β/(1−α)), log((1−β)/α)]`; нижняя → принять H0, верхняя → принять H1. α=β=0.05: ±ln19 = ±2.9444. Другие [SIM]: (α=0.01, β=0.05) → [−2.9857, 4.5539]; (0.05, 0.2) → [−1.5581, 2.7726]; (0.01, 0.01) → ±4.5951.
- **Точный LLR для биномиальных исходов** (win/loss без ничьих): `LLR = W·ln(p1/p0) + L·ln((1−p1)/(1−p0))`, `p_i = 1/(1+10^{−elo_i/400})`. [МОЁ, стандартная формула; проверена симуляцией ниже].
- **Приближение GSPRT (2.1)**: `LLR ≈ ½ (φ1−φ0)(2φ̂ − φ0 − φ1) / V(φ̂)`, где `V(φ̂)` — оценка дисперсии φ̂: `V = (1/N)(−φ̂² + Σ a_i² p̂_i)` для `φ = Σ a_i p_i` (мультиномиальная модель).
  - Trinomial (W/D/L): a = (1, ½, 0).
  - **Pentanomial** (пары игр с обменом цветами): 5 исходов пары (LL, LD, DD/WL, WD, WW), a = (0, ¼, ½, ¾, 1); N = число *пар* (игр/2). Даёт "substantial saving of testing resources" [V wiki] — учитывает корреляцию внутри пары (один и тот же opening/seed).
- **Итоговая формула fishtest (4.14)** в normalized t-value: `LLR ≈ (N/2)·ln[(1 + (t̂_n − t_{n,0})²)/(1 + (t̂_n − t_{n,1})²)]`; упрощение (4.15): `LLR ≈ (N/2)(t_{n,1} − t_{n,0})(2t̂_n − t_{n,0} − t_{n,1})`; регуляризация: `LLR/N` зажимать в `[−(t1−t0)/2, (t1−t0)/2]`, т.к. в начале σ̂≈0.
- **Normalized Elo**: `t_n = (μ − ½)/σ_pg`; `e_n = C·t_n`, `C = 2/β = 800/ln10 ≈ 347.43`, `β = ln10/400`. Для сбалансированного набора и доли ничьих d: `σ_pg = ½√(1−d)`, `e_n ≈ e_l/√(1−d)` (e_l — logistic Elo). Значит normalized Elo *не зависит от draw rate*, а logistic — зависит: таблица из статьи (e_n = 5.00):

| Draw ratio | 0.00 | 0.30 | 0.50 | 0.60 | 0.70 | 0.80 | 0.90 |
|---|---|---|---|---|---|---|---|
| Logistic Elo | 5.00 | 4.18 | 3.54 | 3.16 | 2.74 | 2.24 | 1.58 |

- **Ожидаемая длительность** (худший случай, истинная сила посередине между H0 и H1, α=β=0.05): `T = D/(e_{n,1} − e_{n,0})²`, `D = C²·ln(19)² ≈ 1 046 535` [V]:

| Δ normalized Elo (H1−H0) | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| игр | 1 046 535 | 261 634 | 116 282 | 65 408 | 41 861 | 29 070 |

  Если истинная сила = H0 или H1: `D' = 9·C²·ln(19)/5 ≈ 639 770` вместо D (в знаменателе та же Δ²) [V].
  Практическое правило: `T ≈ 10⁶ / Δ²` игр.
- **Типичные границы** (gainer / non-regression), по CPW [V: https://chessprogramming.org/Sequential_Probability_Ratio_Test]:
  - Stockfish LTC: [0.5, 2.5] / [−1.75, 0.25]; Stockfish STC: [0, 2] / [−1.75, 0.25]; топ-30 движков: [0, 3] / [−3, 1]; топ-200: [0, 5] / [−5, 0]; остальные: [0, 10] / [−10, 0].
  - Единицы Elo в этой таблице (BayesElo/logistic/normalized) в разные эпохи fishtest различались [не подтверждено, какие именно в каждой строке]. В статье CPW: "bounds are generally looser for weaker engines and tighter for stronger" (elo compression).
  - Рекомендация CPW: задавать огромное число раундов (напр. 999999), чтобы тест не остановился раньше SPRT.
  - Сообщение fishtest: пока тест не закончен, Elo-оценка SPRT смещена; "SPRT Elo estimates are only unbiased if one takes all patches into account, both passed and non-passed" [V: https://github.com/official-stockfish/fishtest/wiki/Fishtest-faq].

**Как применить к Colosseum** [МОЁ]:
- SPRT удобен для gating "кандидат ≥ текущий лучший" и для "ранний останов" бесполезных кандидатов. Параметры: elo0=0, elo1 = минимальное улучшение, которое вам интересно (напр. 10–20 Elo); для 1v1 с симметричными слотами (side-swap) использовать pentanomial по парам.
- При K кандидатах из одной обучающей линии нужна поправка на множественные сравнения (Bonferroni: α/K, β оставить) — иначе FWER растёт (см. 3.4).
- Для N-игроков: свести матч к "score of candidate vs. field" (например, доля набранных очков ∈[0,1]) и применять GSPRT по эмпирической дисперсии (формула 2.1 универсальна для любого распределения дискретных исходов).

### 3.4 Selection bias / winner's curse при выборе лучшего из многих

- Теория: выбор максимума из шумных оценок → завышение. Нет несмещённого оценивателя максимума ожидаемых значений (van Hasselt, https://arxiv.org/abs/1302.7175 [V abstract]). "A maximum taken over training is a known source of optimistic bias in checkpoint selection" [S: выдача поиска, RL-fine-tuning].
- Аналог в рейтингах: The Leaderboard Illusion (Singh et al. 2025): Meta тестировала **27 приватных вариантов** Llama-4 перед релизом и публиковала лучший; такой best-of-N завышает позицию на Arena [V abstract: https://arxiv.org/abs/2504.20879].
- **Моя симуляция** (sim2.py): K чекпоинтов, истинная сила ~ N(0, sd Elo) относительно benchmark; каждый оценён n играми; выбираем лучший по наблюдаемому win-rate. Завышение (Elo) выбранного и P(выбрать истинно лучшего) [SIM, 2000 повторов]:

|---|---|---|---|---|
| 5 | 100 | 0 | 41.0 | 0.21 |
| 5 | 400 | 0 | 20.2 | 0.20 |
| 5 | 400 | 20 | 13.4 | 0.58 |
| 5 | 1600 | 20 | 4.1 | 0.75 |
| 20 | 100 | 20 | 57.9 | 0.20 |
| 20 | 400 | 0 | 32.1 | 0.04 |
| 20 | 400 | 20 | 21.4 | 0.41 |
| 20 | 400 | 50 | 11.0 | 0.68 |
| 20 | 1600 | 20 | 6.9 | 0.61 |
| 100 | 400 | 0 | 43.8 | 0.01 |
| 100 | 400 | 20 | 29.0 | 0.28 |
| 100 | 1600 | 20 | 9.2 | 0.49 |
| 100 | 1600 | 50 | 4.0 | 0.76 |

Вывод: типичные соседние чекпоинты различаются на 5–20 Elo, а 400 игр дают ±34 Elo → выбрать "лучший из 20" практически лотерея; ожидаемое завышение 20–30 Elo. **Лечение**:
1. Финалист(ы) перемеряется на **независимых** играх (новые сиды, новые оппоненты/слоты) — несмещённая оценка победителя.
2. Выбор по сглаженной кривой (скользящее среднее/регрессия рейтинга по шагам обучения), а не по argmax шумных точек.
3. Симультанные CI (Bonferroni; либо χ²-доверительное множество с sandwich-ковариацией, как в Arena [V]) и approximate rank `R_m = 1 + Σ 1{inf C_m' > sup C_m}`: чекпоинты, чьи интервалы перекрываются с лучшим, считаются неразличимыми → выбирать среди них по другому критерию (min exploitability, последний, средний вес).
4. Тест "лучший vs последний" с SPRT/CI на разность, а не сравнение точечных оценок.

### 3.5 Successive halving / best-arm identification для чекпоинтов

- Jamieson & Talwalkar, "Non-stochastic Best Arm Identification and Hyperparameter Optimization": bandit-постановка, ресурс концентрируется на перспективных конфигурациях; "comparable test accuracies an order of magnitude faster" [V abstract: https://arxiv.org/abs/1502.07943].
- Алгоритм Successive Halving (классический вид, формула из памяти, [не подтверждено в извлечённом тексте]): бюджет B, n арок; на каждом из `⌈log₂ n⌉` раундов каждой оставшейся арке выдаётся `B/(|S_k|·⌈log₂ n⌉)` розыгрышей, затем отбрасывается нижняя половина по эмпирическому среднему.
- Применение [МОЁ]: K чекпоинтов (arms) → раунд 1: по m игр против benchmark каждому; отбросить нижнюю половину; удвоить m для оставшихся; … финал: 2 кандидата с наибольшим числом игр + независимый hold-out. Экономит ~4–10× игр при том же числе K (грубо, зависит от разброса).
- Ограничение: SH использует нестационарный/переиспользуемый счёт — финальная оценка победителя тоже смещена → п.1 из 3.4 (повторное независимое измерение) обязателен.
- Альтернативы: fixed-confidence BAI (LUCB, Racing) — не проверял [не подтверждено].

### 3.6 "Последний" vs "лучший"

- AlphaZero отказался от best-selection: самоигра всегда ведётся последней сетью ("omitting the evaluation step and the selection of best player") [V: https://arxiv.org/pdf/1712.01815]. KataGo вернул gating, но лёгкий [V: https://arxiv.org/abs/1902.10565 Appendix E].
- При отсутствии надёжной оценки "последний" часто устойчивее, чем argmax шумных замеров (см. winner's curse). [МОЁ]: правило: брать **последний чекпоинт из "плато"**, если его CI на разность с argmax-чекпоинтом включает 0; иначе брать argmax, но перемеренный на hold-out.
- В RL-PPO качество колеблется между чекпоинтами (policy collapse, forgetting): отдельно мониторить min win-rate против исторических чекпоинтов (forgetting proxy AlphaStar) [V].

### 3.7 Усреднение весов (SWA / EMA / model soups)

- **SWA** (Izmailov et al., UAI 2018): среднее весов вдоль траектории SGD → более плоские оптимумы, лучше обобщение, почти нулевая стоимость [V abstract: https://arxiv.org/abs/1803.05407].
- **Model soups** (Wortsman et al.): uniform soup (равное среднее), **greedy soup** (добавлять модель в суп, только если улучшается валидация); 90.94% top-1 ImageNet с ViT-G; работает, когда модели в одном loss-бассейне [V abstract: https://arxiv.org/abs/2203.05482].
- **KataGo** уже применяет это в RL-цикле: каждые ~250 000 сэмплов снапшот, каждые 4 снапшота кандидат = EMA снапшотов (decay=0.75, 4 в lookback), кандидат проходит gating ≥100/200 [V: https://arxiv.org/pdf/1902.10565, Section 3/Appendix E].
- Для Colosseum [МОЁ]: (а) EMA весов на learner как публикуемая политика (дёшево, снижает шум оценки и variance между чекпоинтами → меньше winner's curse); (б) "soup" последних K чекпоинтов с greedy-проверкой на hold-out; ограничение — для LSTM/GRU и разных seed-ов усреднение может ломаться (loss-бассейны), проверять матчем. Прямых результатов для self-play RL с LSTM в извлечённых источниках нет [не подтверждено].

### 4.2 Статистические свойства порога "55% за 400" и "50% за 200" [SIM, sim2.py; бином]

P(пропуск) для кандидата с истинной разницей ΔElo:

| ΔElo | p | AGZ: ≥220/400 | KataGo: ≥100/200 |
|---|---|---|---|
| −20 | 0.471 | 0.001 | 0.228 |
| −10 | 0.486 | 0.006 | 0.368 |
| 0 | 0.500 | 0.026 | 0.528 |
| +10 | 0.514 | 0.084 | 0.684 |
| +20 | 0.529 | 0.212 | 0.812 |
| +35 | 0.550 | 0.524 | 0.933 |
| +50 | 0.571 | 0.821 | 0.982 |
| +70 | 0.599 | 0.980 | 0.998 |
| +100 | 0.640 | 1.000 | 1.000 |

Интерпретация:
- AGZ-правило **консервативно**: порог 55% ↔ +35 Elo. Кандидат с +10 Elo проходит лишь в 8% — для медленного RL-прогресса "по 5–10 Elo за шаг" gating застрянет (stalled nets) — это известная проблема, поэтому AlphaZero его убрал.
- KataGo-правило **почти "не хуже"**: 100/200 пропускает кандидата с 0 Elo в 53% случаев и с −10 Elo — в 37% (т.е. gating защищает только от явной деградации ≳ −30 Elo), зато не блокирует прогресс.
- SPRT с (elo0, elo1) даёт явный контроль α/β и меньше игр в среднем при тех же ошибках (см. 3.3).

### 4.3 AlphaStar snapshot/lиг-правила (Methods) [V: AlphaStar PDF]

- Main agents: 35% self-play, 50% PFSP против всех прошлых игроков лиги, 15% PFSP против "забытых" main-игроков (которых агент уже не бьёт) и прошлых main exploiters (если таких нет — 15% идёт в self-play). **Снапшот каждые 2·10^? шагов** (показатель в извлечённом тексте повреждён; значение [не подтверждено]); main agents не сбрасываются.
- League exploiters: PFSP; замороженная копия добавляется в лигу, когда агент выигрывает у **всех** игроков лиги в >70% игр, либо по таймауту (показатель степени повреждён [не подтверждено]); затем 25% вероятность сброса на supervised-параметры.
- Main exploiters: играют с main agents; половину времени (если P(win) < 20%) PFSP с `f_var` по снапшотам main-агентов; добавляются в лигу, когда **все три** main агента побеждены в >70% игр, либо по таймауту; затем всегда сброс на supervised.
- Т.е. "gating" AlphaStar — порог 70% **против всех** (для exploiters) — условие входа "полезного" оппонента; для main — временной снапшот без порога.

### 4.4 Плюсы/минусы

| Подход | Плюсы | Минусы |
|---|---|---|
| Жёсткий порог win-rate (55%/400) | простая интерпретация; защищает от деградации и от шума; чистый "best" для self-play | дорого (400 игр на каждый кандидат), блокирует мелкий прогресс (+10 Elo проходит в 8%), "лучший" = argmax по одному матчу → winner's curse; нетранзитивность игнорируется |
| Мягкий порог (KataGo 100/200) | дёшево, почти не блокирует; ловит коллапс | пропускает слегка худшие сети (0 Elo → 53%, −10 → 37%) |
| SPRT-gating | контролируемые α, β; меньше игр в среднем; ранний отказ | нужно задать elo0/elo1; при N игроках — эмпирическая дисперсия; множественные сравнения |
| Без gating (AlphaZero) | нет простоя, максимум скорости | нет защиты от деградации/forgetting; нужны робастные оппоненты/пул (PFSP/exploiters) |
| Расписание + min-winrate (AlphaStar) | совместимо с PFSP, пул растёт всегда; exploiters входят по порогу 70% | пул разрастается → нужен FIFO/прореживание; нужна метрика forgetting |

Рекомендация для Colosseum [МОЁ]: оставить FIFO-снапшоты (как в CLAUDE.md) без жёсткого gating для **тренировочного пула**; ввести **мягкий gating только для "публикации/сабмита"** (SPRT против текущего "champion" и против benchmark, с Bonferroni при K кандидатах). Для "arena"-матчей trainable-агентов gating не нужен.

### 5.1 openskill (v6.2.0, MIT) — https://openskill.me , https://github.com/OpenDebate/openskill.py [GitHub URL из памяти; документация проверена]

```python
from openskill.models import PlackettLuce
m = PlackettLuce()                       # mu=25, sigma=25/3, beta=25/6, tau=25/300, kappa=1e-4
a, b, c, d = [m.rating(name=n) for n in "abcd"]

# 1v1
[[a1], [b1]] = m.rate([[a], [b]])        # первый выигрывает: mu 27.635 / 22.365, sigma 8.066

# FFA, ranks (меньше = лучше), ничья за 2-е место
r = m.rate([[a], [b], [c], [d]], ranks=[1, 2, 2, 4])
# mu: 27.80, 24.69, 24.69, 22.83

# по очкам (выше = лучше) и веса частичного участия
m.rate([[a], [b], [c]], scores=[10, 5, 5])
m.rate(match, weights=[[20], [1], [3], [15]])

# предсказания
m.predict_win([[a], [b]])                # [0.5, 0.5]
m.predict_draw([[a], [b]])               # 0.237 (между двумя новичками)
m.predict_rank([[a], [b], [c]])          # [(rank, prob), ...]

# консервативный рейтинг
a1.ordinal()                             # mu - 3*sigma (z=3.0, alpha=1, target=0)
```
Другие модели: `BradleyTerryFull/Part`, `ThurstoneMostellerFull/Part` (импорт из `openskill.models`). Сигнатура `rate(teams, ranks=None, scores=None, weights=None, tau=None, limit_sigma=None)`.
Плюсы: FFA/ranks/ties/teams/weights, предсказания, быстро, Pure Python. Минусы: нет CI в Elo-шкале (сигму переводить вручную), дефолты осторожнее TrueSkill (первая игра ±2.6 vs ±4.4).

### 5.3 choix (v0.4.1, MIT) — https://github.com/lucasmaystre/choix , доки https://choix.lum.li

Функции: `ilsr_pairwise`, `lsr_pairwise`, `mm_pairwise`, `opt_pairwise`, `ep_pairwise` (Bayesian EP), `ilsr_rankings` (Plackett–Luce), `ilsr_top1`, `choicerank`, `probabilities`, `compare`.
```python
import choix
data = [(0, 1), (0, 1), (1, 0), (1, 2), (2, 1), (1, 2), (0, 2), (0, 2), (2, 0)]  # (winner, loser)

EP-ковариация в моём тесте оказалась очень широкой при α=0.01 на маленьком наборе (std ≈ 5.8) — осторожно с выбором prior.

ws = [Winner.X, Winner.X, Winner.Y, Winner.X, Winner.X, Winner.Draw]

```
Сигнатура `bradley_terry(xs, ys, winners, index=None, weights=None, win_weight=1.0, tie_weight=0.5, solver='pyo3', tolerance=1e-6, limit=100)`. Плюсы: быстрый, ничьи (tie_weight), веса, pandas, bootstrap. Минусы: свежая библиотека (0.4.x), нет sandwich CI из коробки, FFA только через попарные записи.

## 6. Что внедрять (приоритеты) [МОЁ]

P0 (дёшево, высокий эффект):
1. Хранить **сырые результаты матчей** (agent ids, слоты, placement/score, seed, фаза) — любую систему можно пересчитать (batch BT/OpenSkill/α-Rank).
2. Добавить **batch BT-MLE с L2 к рейтингу родителя** и **bootstrap по матчам** (1000 реплик); оставить текущий Elo как online-индикатор, но не использовать для отбора.
3. В `eval` для N-игроков: score = нормированные очки, CI — Wilson для бинарных, bootstrap для остальных; **рассчитывать число игр по таблице 3.1**.
4. Hold-out: финальный отбор из top-K по точечным рейтингам → перемеренный на независимых сидах/слотах; отчёт с winner's-curse оценкой.

P1:
5. SPRT-gating (GSPRT, pentanomial при side-swap парах) для публикации; Bonferroni при K кандидатах.
6. OpenSkill PlackettLuce вместо Elo для онлайн-рейтинга N-игроков (sigma → приоритет матчмейкинга: играть чекпоинтами с большой sigma).
7. Диагностика цикличности (curl/disc) + Nash average для пула; метрика forgetting (min win-rate vs прошлые) и RPP между запусками/популяциями.

P2:
8. EMA/SWA весов learner'а для публикуемой политики; greedy soup из последних K чекпоинтов с проверкой на hold-out.
9. α-Rank для малых N-игроковых лиг (только если число профилей приемлемо).
